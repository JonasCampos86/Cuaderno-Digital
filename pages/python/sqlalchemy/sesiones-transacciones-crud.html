Sesiones, transacciones y CRUD

Ciclo de vida de la sesión, transacciones, consultas y validaciones.

1. Qué es una sesión

Los fragmentos continúan la configuración de las lecciones anteriores: se reutilizan Base, engine, SessionLocal y los modelos según corresponda.

La Session es el espacio de trabajo utilizado por SQLAlchemy ORM para consultar objetos, registrar cambios y coordinar una transacción.

La sesión mantiene temporalmente los objetos con los que trabaja y solicita una conexión al Engine cuando necesita comunicarse con la base de datos.

Una sesión reúne operaciones relacionadas que deben confirmarse o deshacerse juntas.

2. Fábrica de sesiones

Configuración habitual:

from sqlalchemy.orm import sessionmaker

SessionLocal = sessionmaker(
    bind=engine,
    autoflush=False,
)

SessionLocal es una fábrica. Cada llamada crea una sesión independiente:

session = SessionLocal()

La sesión debe cerrarse al terminar:

session.close()

Es preferible garantizar el cierre mediante with:

with SessionLocal() as session:
    usuarios = session.scalars(select(Usuario)).all()

with SessionLocal() garantiza el cierre, pero no hace commit automáticamente. Para confirmar al salir usamos SessionLocal.begin() o un commit() explícito.

3. Estados de un objeto ORM

EstadoSignificado
TransitorioExiste en Python, pero no pertenece a una sesión
PendienteSe añadió a la sesión, pero puede no haberse insertado
PersistenteRepresenta una fila asociada a la sesión
EliminadoEl DELETE se ejecutó durante un flush; la transacción aún no ha terminado
SeparadoTiene identidad de base de datos, pero no está asociado a ninguna sesión

Ejemplo:

usuario = Usuario(nombre="Ana", edad=30)  # Transitorio
session.add(usuario)                       # Pendiente
session.flush()                            # Persistente

4. add(), flush() y commit()

add()

Añade un objeto a la unidad de trabajo de la sesión.

session.add(usuario)

add() no significa que el INSERT ya se haya ejecutado.

flush()

Sincroniza los cambios pendientes con la base de datos dentro de la transacción actual.

session.add(usuario)
session.flush()
print(usuario.id)

Después del flush pueden estar disponibles valores generados por la base de datos, como la clave primaria.

El flush no confirma la transacción. Todavía puede ejecutarse rollback().

commit()

Confirma la transacción y hace permanentes sus cambios.

session.commit()

commit() ejecuta primero un flush si existen cambios pendientes.

autoflush=False no evita el flush obligatorio realizado por commit().

Con autoflush=False, una consulta puede no reflejar cambios pendientes todavía no enviados. Si necesita verlos, ejecuta flush() antes de consultar.

5. rollback()

rollback() deshace la transacción actual y permite recuperar una sesión después de determinados errores.

session.rollback()

Patrón básico:

from sqlalchemy.exc import SQLAlchemyError

with SessionLocal() as session:
    try:
        usuario = Usuario(nombre="Ana", edad=30)
        session.add(usuario)
        session.commit()
    except SQLAlchemyError as error:
        session.rollback()
        print(f"No se pudo guardar: {error}")

Capturar una excepción sin ejecutar rollback() puede dejar la sesión inutilizable.

6. Transacción automática

El gestor de contexto puede confirmar, revertir y cerrar automáticamente:

with SessionLocal.begin() as session:
    session.add(Usuario(nombre="Ana", edad=30))
    session.add(Usuario(nombre="Carlos", edad=25))

Si el bloque termina correctamente, se ejecuta commit(). Si aparece una excepción, se ejecuta rollback().

8. Crear registros

Un registro

with SessionLocal.begin() as session:
    usuario = Usuario(nombre="Raquel", edad=23)
    session.add(usuario)

Varios registros

usuarios = [
    Usuario(nombre="Bob", edad=30),
    Usuario(nombre="María", edad=20),
    Usuario(nombre="Carlos", edad=35),
]

with SessionLocal.begin() as session:
    session.add_all(usuarios)

Los valores deben respetar los tipos del modelo. Una edad debe enviarse como entero.

9. Leer registros

Todos los registros

Sintaxis recomendada en SQLAlchemy 2.x:

from sqlalchemy import select

with SessionLocal() as session:
    sentencia = select(Usuario)
    usuarios = session.scalars(sentencia).all()

Sintaxis tradicional:

usuarios = session.query(Usuario).all()

session.query() todavía puede funcionar, pero select() es la forma principal en SQLAlchemy 2.x.

Filtrar

sentencia = select(Usuario).where(Usuario.edad > 25)
usuarios = session.scalars(sentencia).all()

SQL aproximado:

SELECT id, nombre, edad
FROM usuarios
WHERE edad > 25;

Varios criterios

sentencia = select(Usuario).where(
    Usuario.edad >= 20,
    Usuario.edad <= 30,
)

Los criterios separados dentro de where() se combinan mediante AND.

Primer resultado

first() obtiene el primer resultado, pero no añade un límite al SQL. Usamos limit(1) para solicitar como máximo una fila. Sin order_by(), no se garantiza cuál será la primera.

sentencia = select(Usuario).where(Usuario.nombre == "Ana").limit(1)
usuario = session.scalars(sentencia).first()

Buscar por clave primaria

usuario = session.get(Usuario, 1)

Para buscar por clave primaria, session.get() expresa mejor la intención.

10. Agregaciones

Contar usuarios:

from sqlalchemy import func, select

sentencia = select(func.count(Usuario.id))
total = session.scalar(sentencia)

Calcular la edad media:

sentencia = select(func.avg(Usuario.edad))
edad_media = session.scalar(sentencia)

Si MySQL puede realizar la agregación, normalmente es preferible no cargar todas las filas en Python.

11. Actualizar registros

Los objetos recuperados por la sesión son vigilados por SQLAlchemy. Al modificar un atributo y confirmar la transacción, el ORM genera el UPDATE.

with SessionLocal.begin() as session:
    usuario = session.get(Usuario, 1)

    if usuario is not None:
        usuario.edad = 31

SQL aproximado:

UPDATE usuarios
SET edad = 31
WHERE id = 1;

Un parámetro opcional no debe comprobarse únicamente por su valor de verdad:

# Evitar si 0 es un valor permitido
if nueva_edad:
    usuario.edad = nueva_edad

# Correcto
if nueva_edad is not None:
    usuario.edad = nueva_edad

12. Eliminar registros

with SessionLocal.begin() as session:
    usuario = session.get(Usuario, 1)

    if usuario is not None:
        session.delete(usuario)

delete() marca el objeto. El DELETE se ejecuta durante el siguiente flush.

13. Validaciones

Existen dos niveles diferentes de validación.

Validación en Python

def validar_usuario(nombre: str, edad: int) -> None:
    if not nombre.strip():
        raise ValueError("El nombre es obligatorio")

    if edad < 0:
        raise ValueError("La edad no puede ser negativa")

Restricciones en la base de datos

nombre: Mapped[str] = mapped_column(
    String(100),
    nullable=False,
)
edad: Mapped[int] = mapped_column(nullable=False)

La validación de Python mejora la experiencia de uso, pero no sustituye las restricciones de MySQL.

nullable=False impide NULL, pero por sí solo no impide un nombre vacío ni una edad negativa. Esas reglas requieren las validaciones o restricciones adicionales correspondientes.

14. Sesiones con duración limitada

Debe evitarse una sesión global abierta al importar un módulo:

# Evitar como diseño general
session = SessionLocal()

Es preferible abrirla donde comienza la operación:

def crear_usuario(nombre: str, edad: int) -> None:
    with SessionLocal.begin() as session:
        session.add(
            Usuario(nombre=nombre, edad=edad)
        )

Cada operación o petición debe tener un límite claro para su sesión.

Ciclo habitual de una operación:

  • Abrir una sesión al comenzar la operación o petición.
  • Realizar con ella las consultas y cambios que formen parte de esa operación.
  • Ejecutar commit() si todo termina correctamente o rollback() si se produce un error.
  • Cerrar la sesión al finalizar.

Regla práctica: una sesión por operación o petición completa; no una sesión distinta para cada objeto ni una sesión global durante toda la vida de la aplicación.

Abrir y cerrar sesiones es una operación ligera. La sesión solicita una conexión al Engine cuando la necesita y, al cerrarse, normalmente la devuelve al conjunto de conexiones para que pueda reutilizarse.

Cerrar una sesión no confirma sus cambios. close() libera recursos y revierte una transacción pendiente; si queremos conservar modificaciones debemos confirmarlas antes, explícitamente o mediante SessionLocal.begin().

15. Errores frecuentes

No cerrar la sesión.

Capturar Exception y ocultar el error real.

Olvidar rollback() después de un error.

Suponer que una columna rechaza NULL sin revisar su nulabilidad: puede declararse con nullable=False o inferirse de una anotación Mapped no opcional.

Pasar números como cadenas.

Ejecutar repetidamente un script que siempre inserta los mismos datos.

Utilizar identificadores fijos suponiendo que existen.

Confundir add() con un INSERT ya confirmado.

16. Resumen

La sesión coordina los objetos y la transacción.

add() registra cambios pendientes.

flush() envía cambios sin confirmar la transacción.

commit() confirma los cambios.

rollback() revierte la transacción actual.

close() libera los recursos de la sesión.

Un CRUD correcto también necesita validaciones, transacciones y un ciclo de vida claro para la sesión.
