Fundamentos de ORM y SQLAlchemy

Objetos, SQL, conexión, modelos y creación de tablas.

1. Qué es un ORM

Un ORM (Object-Relational Mapping) es una herramienta que relaciona el modelo de objetos de un lenguaje de programación con una base de datos relacional.

En Python trabajamos con clases, objetos y atributos. En MySQL trabajamos con tablas, filas y columnas. El ORM traduce las operaciones realizadas con objetos a instrucciones SQL.

Referencia entre objetosRelación apoyada normalmente en una clave foránea

Estas equivalencias son aproximaciones didácticas. Una clave foránea y una relación del ORM no son lo mismo:

  • La clave foránea es una restricción sobre una o varias columnas de la base de datos.
  • La relación ORM es una propiedad de Python que permite navegar entre objetos relacionados.

El ORM no sustituye SQL. Genera SQL y lo ejecuta mediante un controlador.

2. Qué aporta un ORM

Un ORM permite:

  • Definir tablas mediante clases.
  • Crear registros mediante objetos.
  • Consultar, actualizar y eliminar datos.
  • Representar relaciones entre tablas.
  • Gestionar transacciones mediante sesiones.
  • Mantener el acceso a datos integrado con Python.

Objeto creado en Python:

usuario = Usuario(nombre="Ana", edad=30)

SQL aproximado cuando el objeto se guarde:

INSERT INTO usuarios (nombre, edad)
VALUES ('Ana', 30);

Crear el objeto no ejecuta todavía el INSERT. Primero debe añadirse a una sesión y sincronizarse con la base de datos.

3. Qué no hace un ORM

Utilizar un ORM no elimina la necesidad de conocer:

  • Tablas y tipos de datos.
  • Claves primarias y foráneas.
  • Relaciones.
  • Restricciones.
  • Índices.
  • Transacciones.
  • Normalización.
  • Consultas SQL.
  • Planes de ejecución y rendimiento.

Un ORM tampoco garantiza:

  • Que todas las consultas sean eficientes.
  • Que el diseño de la base de datos sea correcto.
  • Que nunca exista una inyección SQL.
  • Que no aparezcan consultas innecesarias.
  • Que cambiar de motor de base de datos sea automático.

Saber SQL permite comprender, comprobar y optimizar el trabajo realizado por el ORM.

5. Variables de entorno

Las credenciales no deben escribirse directamente en el código ni publicarse en GitHub.

Archivo .env:

DB_USER=usuario_aplicacion
DB_PASSWORD=contraseña_local
DB_HOST=localhost
DB_PORT=3306
DB_NAME=clase1

Carga de las variables:

import os
from dotenv import load_dotenv

load_dotenv()

password = os.getenv("DB_PASSWORD")

if not password:
    raise RuntimeError("No se ha definido DB_PASSWORD")

Importar load_dotenv no carga el archivo. Debe ejecutarse load_dotenv().

Archivos que deben excluirse de Git:

.env
__pycache__/
*.pyc

Puede crearse un .env.example sin contraseñas reales para documentar las variables necesarias.

6. URL de conexión y Engine

El Engine administra la comunicación con la base de datos y el conjunto de conexiones disponibles.

Configuración recomendada:

import os
from dotenv import load_dotenv
from sqlalchemy import URL, create_engine

load_dotenv()

password = os.getenv("DB_PASSWORD")

if not password:
    raise RuntimeError("Falta la variable DB_PASSWORD")

database_url = URL.create(
    drivername="mysql+pymysql",
    username=os.getenv("DB_USER", "usuario_aplicacion"),
    password=password,
    host=os.getenv("DB_HOST", "localhost"),
    port=int(os.getenv("DB_PORT", "3306")),
    database=os.getenv("DB_NAME", "clase1"),
)

engine = create_engine(database_url, echo=True)

mysql+pymysql indica:

  • mysql: dialecto de la base de datos.
  • pymysql: controlador utilizado para conectarse.

URL.create() evita problemas con caracteres especiales en la contraseña.

echo=True muestra en la terminal el SQL generado. Es útil para estudiar y depurar.

En producción normalmente se utiliza echo=False porque el registro puede ser extenso y mostrar información sensible.

create_engine() no crea la base de datos indicada en la URL. La base de datos debe existir previamente.

7. Clase base declarativa

Todos los modelos heredan de una clase base común. SQLAlchemy registra en ella las tablas y columnas declaradas.

Estilo recomendado en SQLAlchemy 2.x:

from sqlalchemy.orm import DeclarativeBase


class Base(DeclarativeBase):
    pass

Estilo tradicional:

from sqlalchemy.orm import declarative_base

Base = declarative_base()

El estilo tradicional todavía puede funcionar, pero DeclarativeBase es la opción moderna y se integra mejor con el tipado.

Debe evitarse la importación antigua:

from sqlalchemy.ext.declarative import declarative_base

8. Definición de un modelo

Modelo moderno:

from sqlalchemy import String
from sqlalchemy.orm import Mapped, mapped_column


class Usuario(Base):
    __tablename__ = "usuarios"

    id: Mapped[int] = mapped_column(primary_key=True)
    nombre: Mapped[str] = mapped_column(
        String(100),
        nullable=False,
    )
    edad: Mapped[int] = mapped_column(nullable=False)
ElementoSignificado
UsuarioClase mapeada
BaseRegistro común de modelos
__tablename__Nombre real de la tabla
Mapped[int]Tipo esperado en Python
mapped_column()Configuración de la columna
primary_key=TrueClave primaria
nullable=FalseEquivalente a NOT NULL
String(100)VARCHAR(100) en MySQL

MySQL necesita una longitud para los campos VARCHAR:

# Evitar
nombre = Column(String)

# Correcto
nombre = Column(String(100))

Una clave primaria ya dispone de índice. Normalmente no necesita index=True.

Las anotaciones de tipos ayudan a describir el modelo, pero no sustituyen la validación de los datos de entrada en tiempo de ejecución.

Los valores enviados deben respetar el tipo del modelo:

# Evitar
Usuario(nombre="Bob", edad="30")

# Correcto
Usuario(nombre="Bob", edad=30)

10. Creación de tablas

Después de importar todos los modelos:

Base.metadata.create_all(bind=engine)

create_all() comprueba qué tablas registradas no existen y ejecuta los CREATE TABLE necesarios.

Si se ejecuta antes de importar o definir los modelos, Base.metadata puede estar vacío y no habrá tablas que crear.

create_all() no modifica automáticamente tablas existentes. No sustituye a las migraciones.

En proyectos reales suele utilizarse Alembic para:

  • Añadir o eliminar columnas.
  • Cambiar tipos.
  • Crear restricciones.
  • Mantener un historial de cambios.

11. Observar el SQL generado

Con echo=True pueden observarse consultas parecidas a estas:

INSERT INTO usuarios (nombre, edad)
VALUES (%s, %s);
SELECT usuarios.id, usuarios.nombre, usuarios.edad
FROM usuarios
WHERE usuarios.edad > %s;

Si una operación es lenta o inesperada, debe revisarse el SQL generado y su plan de ejecución.

12. Resumen

El ORM relaciona objetos con datos almacenados en tablas.

SQLAlchemy genera SQL, pero MySQL continúa almacenando y validando los datos.

Engine administra la comunicación con la base de datos.

Base registra los modelos.

Un modelo define la correspondencia entre una clase y una tabla.

create_all() crea tablas ausentes, pero no realiza migraciones.

Comprender SQL continúa siendo imprescindible para utilizar correctamente un ORM.
