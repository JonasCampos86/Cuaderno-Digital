Tipos de eventos más relevantes

Diferentes eventos que podemos escuchar en JavaScript según la interacción que queramos detectar.

1. Introducción

Una vez comprendido cómo gestionar eventos mediante addEventListener(), podemos utilizar distintos tipos de eventos dependiendo de la interacción que queramos detectar.

Para gestionar los eventos utilizaremos addEventListener().

Podemos reaccionar a interacciones con formularios, acciones del ratón, pulsaciones de teclado, reproducción multimedia, carga del documento, cambios en la ventana y acciones del portapapeles. 

EVENTOS
  │
  ├── Formularios
  ├── Ratón
  ├── Teclado
  ├── Multimedia
  └── Otros eventos

2. Eventos de formulario

Los formularios permiten introducir datos en una aplicación web.

Sus distintos controles permiten recibir información introducida por el usuario.

Algunos controles habituales son input, select, textarea y button.

Normalmente estos controles se encuentran dentro de un elemento form. 

<form>
  ...
</form>

3. document.forms

document.forms contiene los formularios existentes en el documento.

Podemos acceder a ellos mediante su posición. 

const primerForm = document.forms[0];
document
   ↓
forms
   ↓
┌──────────┬──────────┬──────────┐
│ forms[0] │ forms[1] │ forms[2] │
└──────────┴──────────┴──────────┘

El primer formulario será document.forms[0].

El segundo formulario será document.forms[1].

document.forms permite acceder directamente a los formularios sin tener que buscarlos mediante otros selectores del DOM.

8. preventDefault()

preventDefault() permite impedir el comportamiento predeterminado asociado a un evento.

Por ejemplo, un enlace normalmente intenta navegar hacia la dirección indicada en su atributo href. 

<a href="http://google.com" id="buttonSubmit">
  Enviar
</a>

Podemos capturar su evento y evitar inicialmente esa navegación. 

buttonSubmit.addEventListener(
  "click",
  (event) => {
    event.preventDefault();
  }
);

Después podemos ejecutar nuestra propia lógica antes de permitir otra acción. 

Usuario hace click
      ↓
Evento "click"
      ↓
preventDefault()
      ↓
Se impide la acción predeterminada
      ↓
Ejecutamos nuestra lógica

preventDefault() no elimina el evento: evita su comportamiento predeterminado.

9. Ejemplo práctico: validación de correo

Podemos comprobar el valor introducido antes de enviar el formulario. 

const primerForm = document.forms[0];

if (
  primerForm.elements[0]
    .value
    .includes("@")
) {
  primerForm.submit();
} else {
  alert(
    "Debe añadir una @ en el campo de texto"
  );
}
Formulario
    ↓
elements[0]
    ↓
value
    ↓
includes("@")

Podemos acceder al valor de un control mediante elements y value antes de decidir qué acción realizar.

10. Evento submit

submit se produce cuando se intenta enviar un formulario. 

primerForm.addEventListener(
  "submit",
  (event) => {
    event.preventDefault();

    // Validación
  }
);

Podemos detener inicialmente el envío, comprobar los datos y decidir posteriormente si permitimos continuar.

Ejemplo de validación de edad

primerForm.addEventListener(
            "submit",
            (event) => {
                event.preventDefault();

                const edad =
                document.getElementById("age").value;

                if (edad >= 18 && edad <= 30) {
                errorElement.textContent = "";
                primerForm.submit();
                } else {
                errorElement.textContent =
                    "Debe introducir una edad entre 18 y 30 años";
                }
            }
            );
Usuario intenta enviar
        ↓
      submit
        ↓
  preventDefault()
        ↓
     Validamos
      /      \
 Válido    No válido
   ↓           ↓
submit()     Error

Capturar submit permite ejecutar una validación antes del envío del formulario.

11. ¿Dónde debemos validar: Frontend o Backend?

La validación debe realizarse tanto en el Frontend como en el Backend.

Frontend

En el Frontend la validación sirve principalmente para mejorar la experiencia del usuario.

Permite detectar errores de forma inmediata y mostrar mensajes antes de enviar los datos.

Por ejemplo: avisar de que un campo está vacío, comprobar que una edad está dentro de un rango o detectar que un correo no tiene el formato esperado. 

Usuario introduce datos
        ↓
Frontend valida
        ↓
Detecta errores
        ↓
Muestra feedback inmediato
        ↓
Mejor experiencia de usuario

El Frontend ayuda al usuario a corregir los datos antes de enviarlos.

Backend

En el Backend la validación es la encargada de comprobar que los datos recibidos cumplen realmente las reglas de la aplicación.

No debemos confiar únicamente en la validación realizada en el navegador, porque puede ser evitada o manipulada. 

Datos enviados
      ↓
Backend recibe
      ↓
Valida
      ↓
Comprueba reglas
      ↓
Acepta o rechaza los datos

El Backend debe validar siempre los datos antes de procesarlos.

Comparativa

Lugar Objetivo principal
Frontend Mejorar la experiencia del usuario y ofrecer feedback inmediato
Backend Comprobar que los datos cumplen realmente las reglas de la aplicación 
                 VALIDACIÓN
                     │
          ┌──────────┴──────────┐
          │                     │
      FRONTEND               BACKEND
          │                     │
 Feedback inmediato       Validación fiable
 Experiencia usuario      Reglas de la aplicación
          │                     │
          └──────────┬──────────┘
                     ↓
              Datos correctos

Frontend y Backend no sustituyen uno al otro: ambos deben validar, pero cumplen funciones diferentes.

El Frontend ayuda al usuario; el Backend garantiza que los datos cumplen las reglas de la aplicación.

13. Eventos focus y blur

  }

mouseover Cuando el puntero se sitúa sobre el elemento o alguno de sus hijos
mouseout Cuando el puntero abandona el elemento o alguno de sus hijos

  ├── mouseover / mouseout

15. Evento contextmenu

contextmenu se produce cuando se solicita abrir el menú contextual.

Podemos capturarlo mediante: 

elemento.addEventListener(
  "contextmenu",
  callback
);

Una posible utilización es capturar esa acción e impedir el comportamiento predeterminado.

17. event.key

En los eventos de teclado, la propiedad key contiene información sobre la tecla pulsada. 

elemento.addEventListener(
  "keydown",
  (event) => {
    console.log(event.key);
  }
);
Usuario pulsa una tecla
        ↓
   Keyboard Event
        ↓
     event.key
        ↓
    Tecla pulsada

La información puede variar en función de la tecla y de su combinación con otras teclas.

18. event.location

location permite conocer la zona del teclado desde la que se produjo la pulsación.

Puede resultar útil cuando existen varias teclas equivalentes en diferentes zonas del teclado.

Valor Zona Constante
0 Teclado estándar DOM_KEY_LOCATION_STANDARD
1 Parte izquierda DOM_KEY_LOCATION_LEFT
2 Parte derecha DOM_KEY_LOCATION_RIGHT
3 Teclado numérico DOM_KEY_LOCATION_NUMPAD

19. Eventos de reproducción multimedia

Los eventos multimedia permiten detectar cambios relacionados con la reproducción de elementos multimedia nativos de HTML.

Estos eventos se refieren a elementos multimedia nativos de HTML.

Evento Cuándo se produce
canplay Cuando el contenido puede comenzar a reproducirse
canplaythrough Cuando existen suficientes datos cargados para reproducir el contenido
durationchange Cuando cambia la duración del medio
emptied Cuando el medio se queda sin datos
ended Cuando finaliza la reproducción
loadeddata Cuando se han cargado los primeros datos del medio
loadedmetadata Cuando se han cargado los metadatos
pause Cuando se pausa la reproducción
play Cuando comienza o se reanuda la reproducción
playing Cuando el medio está preparado para reproducirse
ratechange Cuando cambia la velocidad de reproducción
seeked Cuando finaliza una búsqueda dentro del medio
seeking Cuando comienza una búsqueda
stalled Cuando se produce un problema durante la carga
suspend Cuando se suspende la carga
timeupdate Cuando cambia el tiempo actual de reproducción
volumechange Cuando cambia el volumen
waiting Cuando la reproducción se detiene por falta de datos

No es necesario aprender esta lista de memoria.

Lo importante es comprender que diferentes momentos del ciclo de reproducción generan diferentes eventos.

21. DOMContentLoaded

DOMContentLoaded permite ejecutar código cuando el documento HTML ha sido cargado. 

document.addEventListener(
  "DOMContentLoaded",
  () => {
    document
      .getElementById("prueba")
      .textContent = "Hola";
  }
);

        ↓
Se construye el documento
        ↓
DOMContentLoaded

Podemos dejar preparado código para que se ejecute cuando el documento HTML haya sido cargado.

25. Resumen final

addEventListener() permite escuchar diferentes tipos de eventos dependiendo de la interacción que necesitemos detectar.

document.forms permite acceder a los formularios del documento.

elements permite acceder a los controles contenidos dentro de un formulario.

value permite obtener el valor actual de un control.

submit() permite enviar un formulario.

reset() devuelve el formulario a su estado inicial.

preventDefault() permite impedir el comportamiento predeterminado asociado a un evento.

El evento submit permite detectar el intento de envío de un formulario y realizar comprobaciones antes de continuar.

change permite detectar cambios en un control.

focus se produce cuando un elemento recibe el foco y blur cuando lo pierde.

Los eventos de ratón permiten detectar clics, movimientos, entradas y salidas del puntero y otras interacciones.

Los eventos de teclado permiten detectar la pulsación y liberación de teclas.

event.key proporciona información sobre la tecla pulsada.

event.location permite conocer la zona del teclado desde la que se produjo la pulsación.

Los elementos multimedia generan diferentes eventos durante su carga y reproducción.

DOMContentLoaded permite ejecutar código cuando el documento HTML ha sido cargado.

También existen eventos relacionados con la ventana, la impresión y el portapapeles.

Idea principal: cada tipo de interacción genera eventos diferentes, pero el mecanismo de trabajo sigue siendo el mismo. 

elemento.addEventListener(
  "evento",
