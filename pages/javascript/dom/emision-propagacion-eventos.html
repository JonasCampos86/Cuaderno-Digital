Emisión y propagación de eventos

Clase 29 · Crear y emitir eventos, transportar información y controlar su recorrido por el DOM.

1. Introducción

Además de reaccionar a eventos generados por el usuario, JavaScript permite crear y emitir eventos de forma programática.

Podemos utilizar esta posibilidad para:

Simular determinadas interacciones.

Comunicar que ha ocurrido algo dentro de la aplicación.

Crear eventos personalizados.

Transmitir información junto con un evento.

Controlar cómo se propaga un evento por una jerarquía de elementos.

2. Eventos personalizados

Un evento personalizado es un evento creado por nosotros para representar una acción concreta de la aplicación.

Para crearlo utilizamos el objeto CustomEvent.

Sintaxis:

const evento = new CustomEvent(
    "nombreDelEvento",
    opciones
);

El constructor recibe:

ParámetroUtilidad
Nombre del eventoIdentifica el evento que estamos creando
Objeto de opcionesConfigura su contenido y comportamiento

Crear el evento no provoca que se ejecute automáticamente: después tendremos que emitirlo.

Crear evento
     ↓
Registrar listener
     ↓
Emitir evento
     ↓
Ejecutar callback

3. Nombre de un evento personalizado

El primer parámetro de CustomEvent es el nombre que tendrá el evento.

Ejemplo:

const evento = new CustomEvent(
    "usuarioRegistrado"
);

El nombre debe describir claramente la acción que representa el evento.

Algunos nombres utilizados podrían representar acciones como:

usuarioRegistrado
mensajeRecibido
pedidoCompletado

En aplicaciones grandes conviene mantener una convención de nombres coherente y fácil de recordar.

El nombre utilizado al escuchar el evento debe coincidir exactamente con el utilizado al crearlo.

document.addEventListener(
    "usuarioRegistrado",
    callback
);

4. Opciones de CustomEvent

El segundo parámetro es un objeto que permite configurar el contenido y el comportamiento del evento.

Estructura:

const evento = new CustomEvent(
    "usuarioRegistrado",
    {
        detail: {},
        bubbles: false,
        composed: false,
        cancelable: false
    }
);

Tabla de opciones

OpciónValor inicialUtilidad
detailnullContiene la información que queremos transmitir
bubblesfalseIndica si el evento debe propagarse mediante burbujeo
composedfalseIndica si la propagación puede atravesar los límites del Shadow DOM
cancelablefalseIndica si puede cancelarse su comportamiento con preventDefault()

Estas opciones permiten decidir qué información transporta el evento y cómo debe comportarse.

5. Propiedad detail

detail permite incorporar información dentro de un evento personalizado.

Código:

const messageEvent = new CustomEvent(
    "user:data-message",
    {
        detail: {
            from: "Manz",
            message: "Hello!"
        }
    }
);

Los datos enviados pueden recuperarse desde el callback mediante:

event.detail

Funcionamiento

CustomEvent
     ↓
detail
     ↓
Información transportada
     ↓
Callback recibe event.detail

Esto permite que distintas partes de la aplicación se comuniquen sin tener que llamar directamente unas a otras.

6. Emisión de eventos

Emitir un evento significa lanzarlo para que los listeners correspondientes puedan recibirlo.

También podemos emitir de forma programática eventos que normalmente realizaría el usuario.

Por ejemplo, podemos crear un evento click:

const evento = new Event("click");

Después lo emitimos sobre un elemento:

button.dispatchEvent(evento);

dispatchEvent() lanza el evento sobre el elemento desde el que se invoca.

Flujo

new Event("click")
        ↓
Se crea el evento
        ↓
button.dispatchEvent(evento)
        ↓
El botón emite el evento
        ↓
Se ejecutan sus listeners de click

7. Ejemplo de emisión programática

HTML:

<button>Click me</button>
<span class="text">Hover me</span>

JavaScript:

const button =
    document.querySelector("button");

const text =
    document.querySelector(".text");

button.addEventListener(
    "click",
    () => alert("Has pulsado el botón")
);

Cuando el puntero entra en el texto, podemos emitir programáticamente un evento click sobre el botón:

text.addEventListener(
    "mouseenter",
    () => {
        const evento = new Event("click");

        button.dispatchEvent(evento);
    }
);

Resultado

Puntero entra en el texto
          ↓
Se ejecuta mouseenter
          ↓
Se crea un evento click
          ↓
El botón emite el evento
          ↓
Se ejecuta el listener del botón

La emisión programática permite provocar un evento sin que el usuario realice directamente esa acción sobre el elemento.

8. Emisión de un evento personalizado

Para trabajar con un evento personalizado necesitamos:

1. Registrar el listener
2. Crear el CustomEvent
3. Emitirlo con dispatchEvent()
4. Recibirlo en el callback

Primero registramos el listener:

document.addEventListener(
    "usuarioRegistrado",
    (event) => {
        console.log(event.detail);
    }
);

Creamos el evento con información:

const evento = new CustomEvent(
    "usuarioRegistrado",
    {
        detail: {
            nombreUsuario: "Juan",
            motivo: "Registro completado"
        }
    }
);

Finalmente, lo emitimos:

document.dispatchEvent(evento);

Flujo completo

Listener preparado
        ↓
CustomEvent creado
        ↓
Información almacenada en detail
        ↓
dispatchEvent()
        ↓
Callback recibe el evento
        ↓
Consulta event.detail

CustomEvent crea el evento y dispatchEvent() lo pone en circulación.

9. Propagación de eventos

La propagación es el recorrido que realiza un evento a través de la jerarquía de elementos del DOM.

Imaginemos esta estructura:

<div id="padre">
    <button id="hijo">
        Pulsar
    </button>
</div>

Si hacemos clic en el botón, el evento no tiene por qué afectar únicamente al botón.

También puede recorrer los elementos que lo contienen.

document
   │
   └── div#padre
          │
          └── button#hijo

La propagación permite gestionar desde elementos superiores eventos originados en elementos más profundos.

10. Fases de propagación

El recorrido de un evento puede dividirse en tres fases:

CAPTURA
   ↓
OBJETIVO
   ↓
BURBUJEO

Captura

El evento recorre la jerarquía desde los elementos exteriores hasta el elemento donde se originó.

document
   ↓
div padre
   ↓
botón

Objetivo

El evento llega al elemento en el que se ha producido.

Burbujeo

El evento vuelve desde el elemento más profundo hacia los elementos exteriores.

botón
   ↓
div padre
   ↓
document

Esquema completo

              CAPTURA
document → div padre → botón
                        │
                     OBJETIVO
                        │
document ← div padre ← botón
              BURBUJEO

11. Comportamiento de burbuja

En el burbujeo, el evento se gestiona desde el elemento más profundo hacia los elementos que lo contienen.

Si tanto el botón como el div padre escuchan el evento click:

padre.addEventListener(
    "click",
    callbackPadre
);

hijo.addEventListener(
    "click",
    callbackHijo
);

Al pulsar el botón, el orden habitual será:

Click en el botón
       ↓
Listener del botón
       ↓
Listener del padre

El evento se origina en el botón y después burbujea hacia el elemento padre.

12. Cambiar la fase con addEventListener()

El tercer parámetro de addEventListener() permite decidir si el listener debe ejecutarse durante la fase de captura.

Burbujeo:

elemento.addEventListener(
    "click",
    callback,
    false
);

false es el comportamiento predeterminado.

Captura:

elemento.addEventListener(
    "click",
    callback,
    true
);

Con true, el listener actúa durante la fase de captura.

Tercer parámetroFase utilizada
falseBurbujeo
trueCaptura

El tercer parámetro no crea otro evento: cambia la fase en la que participa el listener.

13. Método stopPropagation()

stopPropagation() detiene la propagación del evento por la jerarquía del DOM.

Código:

botonHijo.addEventListener(
    "click",
    (event) => {
        event.stopPropagation();
    }
);

Funcionamiento

Click en el botón
       ↓
Listener del botón
       ↓
stopPropagation()
       ↓
El evento no continúa hacia el padre

El callback del botón puede seguir ejecutando el resto de sus instrucciones.

stopPropagation() no cancela automáticamente el comportamiento predeterminado del navegador.

Tampoco impide que se ejecuten otros listeners registrados en el mismo elemento; únicamente detiene el recorrido del evento hacia otros elementos.

14. Usos de stopPropagation()

SituaciónUtilidad
Botón dentro de un divEvitar que el clic del botón active también el listener del div
Menú contextual dentro de elementos anidadosEvitar que el evento continúe hacia el contenedor exterior
Evento keydownDetener la propagación al pulsar una tecla concreta
Elemento especial dentro de una listaEvitar que el listener delegado del padre procese ese elemento

Ejemplo con un botón dentro de un div

botonHijo.addEventListener(
    "click",
    (event) => {
        event.stopPropagation();

        alert("Clic en el botón hijo");
    }
);

Si el div padre también tiene un listener de click, este no recibirá el evento.

15. Ejemplo con el teclado

Podemos detener la propagación únicamente cuando se pulsa una tecla determinada.

input.addEventListener(
    "keydown",
    (event) => {
        if (event.key === "Enter") {
            event.stopPropagation();

            alert("Has pulsado Enter");
        }
    }
);

Flujo

Usuario pulsa una tecla
          ↓
       keydown
          ↓
¿La tecla es Enter?
     /           \
   Sí             No
    ↓              ↓
stopPropagation()  Continúa normalmente

16. Cancelación del comportamiento predeterminado

Algunos eventos tienen un comportamiento predeterminado establecido por el navegador.

Por ejemplo:

EventoComportamiento predeterminado
submitEnvía el formulario
click en un enlaceNavega hacia la URL
contextmenuAbre el menú contextual
Tecla EspacioPuede desplazar la página
mousedown sobre textoPermite comenzar a seleccionarlo

preventDefault() impide que el navegador ejecute el comportamiento predeterminado asociado al evento.

Código general:

elemento.addEventListener(
    "evento",
    (event) => {
        event.preventDefault();
    }
);

17. Ejemplos de preventDefault()

Impedir el envío automático de un formulario

formulario.addEventListener(
    "submit",
    (event) => {
        event.preventDefault();

        // Validación
    }
);

Impedir que un enlace navegue

enlace.addEventListener(
    "click",
    (event) => {
        event.preventDefault();
    }
);

Impedir el menú contextual

elemento.addEventListener(
    "contextmenu",
    (event) => {
        event.preventDefault();
    }
);

Evitar el desplazamiento con la tecla Espacio

window.addEventListener(
    "keydown",
    (event) => {
        if (event.code === "Space") {
            event.preventDefault();
        }
    }
);

Evitar la selección de texto

elemento.addEventListener(
    "mousedown",
    (event) => {
        event.preventDefault();
    }
);

18. stopPropagation() frente a preventDefault()

Estos métodos no realizan la misma función.

MétodoQué impide
stopPropagation()Que el evento continúe propagándose por otros elementos
preventDefault()Que el navegador ejecute el comportamiento predeterminado
removeEventListener()Que un listener registrado continúe escuchando eventos futuros

Comparación

stopPropagation()
        ↓
Detiene el recorrido del evento

preventDefault()
        ↓
Impide la acción del navegador

removeEventListener()
        ↓
Elimina un listener

Cancelar el comportamiento predeterminado no significa detener la propagación del evento.

En un evento contextmenu podríamos necesitar ambos:

elemento.addEventListener(
    "contextmenu",
    (event) => {
        event.stopPropagation();
        event.preventDefault();
    }
);

Uno impide que el evento llegue a otros elementos y el otro evita que aparezca el menú contextual del navegador.

19. Eventos personalizados cancelables

Para que preventDefault() pueda marcar como cancelado un evento personalizado, debemos crearlo con:

const evento = new CustomEvent(
    "miEvento",
    {
        cancelable: true
    }
);

Después, uno de sus listeners puede utilizar:

event.preventDefault();

La cancelación queda reflejada en:

event.defaultPrevented

La parte de la aplicación que emite el evento debe comprobar esa cancelación para decidir si continúa con su operación.

const aceptado =
    elemento.dispatchEvent(evento);

if (!aceptado) {
    // Algún listener canceló el evento
}

preventDefault() no detiene los callbacks ni elimina el evento. En un evento personalizado, permite comunicar que la operación asociada no debería continuar.

Si cancelable conserva su valor inicial false, preventDefault() no podrá marcar el evento como cancelado.

La opción cancelable debe configurarse al crear el evento personalizado.

20. Eliminar un listener con removeEventListener()

removeEventListener() elimina un manejador que había sido registrado previamente.

Para poder eliminarlo necesitamos conservar una referencia a la misma función:

function manejarClick(event) {
    console.log("Click");
}

button.addEventListener(
    "click",
    manejarClick
);

Después podemos eliminarlo:

button.removeEventListener(
    "click",
    manejarClick
);

Funcionamiento

addEventListener()
        ↓
El listener queda registrado
        ↓
removeEventListener()
        ↓
El listener deja de ejecutarse

Esto no funciona si pasamos otra función diferente:

button.removeEventListener(
    "click",
    () => console.log("Click")
);

Aunque el contenido parezca igual, esa función es un objeto distinto.

Una función anónima introducida directamente en addEventListener() no puede eliminarse posteriormente si no conservamos su referencia.

21. Propiedad event.target

event.target contiene el elemento en el que se originó realmente el evento.

Imaginemos un botón dentro de un div:

<div id="padre">
    <button id="hijo">
        Pulsar
    </button>
</div>

Si pulsamos el botón:

event.target

Será el botón, aunque el listener que está procesando el evento se encuentre en el div padre.

Uso habitual

event.target resulta especialmente útil en la delegación de eventos.

Listener situado en el padre
          ↓
Se pulsa uno de sus hijos
          ↓
event.target
          ↓
Identifica el hijo concreto

22. Propiedad event.currentTarget

event.currentTarget contiene el elemento cuyo listener está procesando actualmente el evento.

Si el listener está registrado en el div padre:

event.currentTarget

Será el div, aunque el clic se haya originado en uno de sus hijos.

Uso habitual

Resulta útil cuando reutilizamos el mismo callback en varios elementos y necesitamos saber cuál de ellos está gestionando el evento.

Mismo callback
      ↓
Varios elementos
      ↓
event.currentTarget
      ↓
Elemento cuyo listener se está ejecutando

23. Comparación entre target y currentTarget

PropiedadRepresenta
event.targetElemento en el que se originó el evento
event.currentTargetElemento cuyo listener lo está procesando

Ejemplo:

padre.addEventListener(
    "click",
    (event) => {
        console.log(event.target);
        console.log(event.currentTarget);
    }
);

Si pulsamos el botón hijo:

event.target
      ↓
button#hijo

event.currentTarget
      ↓
div#padre

target indica dónde comenzó el evento; currentTarget indica dónde se está gestionando.

24. RESUMEN GENERAL

CustomEvent permite crear eventos personalizados.

El primer parámetro identifica el evento y el segundo contiene sus opciones.

detail permite transportar información dentro de un evento personalizado.

bubbles decide si el evento personalizado puede propagarse mediante burbujeo.

cancelable determina si puede marcarse como cancelado mediante preventDefault().

dispatchEvent() emite un evento sobre un elemento.

La propagación es el recorrido del evento por la jerarquía del DOM.

Durante la captura, el recorrido avanza desde los elementos exteriores hacia el objetivo.

Durante el burbujeo, avanza desde el objetivo hacia los elementos exteriores.

El tercer parámetro de addEventListener() permite escuchar durante la fase de captura.

stopPropagation() detiene la propagación hacia otros elementos.

preventDefault() impide el comportamiento predeterminado del navegador o marca como cancelado un evento cancelable.

removeEventListener() elimina un listener registrado.

event.target indica el elemento que originó el evento.

event.currentTarget indica el elemento cuyo listener lo está procesando.
