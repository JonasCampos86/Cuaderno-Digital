Promesas y asincronía

Clase 37 · Crear promesas, gestionar sus resultados y errores, comprender el orden de ejecución y encadenar operaciones.

1. Qué es una promesa y para qué sirve

Algunas operaciones necesitan tiempo para completarse, como pedir datos a un servidor. En lugar de detener todo el programa hasta recibir una respuesta, podemos iniciar una operación asíncrona y continuar ejecutando otras instrucciones.

Una promesa permite trabajar con su resultado: indicar qué hacer cuando la operación tenga éxito y qué hacer si falla.

Una promesa es un objeto que representa el resultado de una operación que puede completarse correctamente o fallar.

Podemos tener una promesa cuyo resultado todavía no esté disponible y dejar preparadas las funciones que actuarán cuando lo esté.

Por ejemplo, al solicitar una lista de productos a un servidor:

  • Mientras esperamos la respuesta, la promesa está pendiente.
  • Si la petición tiene éxito, utilizamos los productos recibidos.
  • Si falla, gestionamos el error.

Estados de una promesa

Estado Significado
pending — Pendiente Todavía no se ha completado.
fulfilled — Cumplida Se ha completado correctamente y tiene un valor de resultado.
rejected — Rechazada Ha fallado y tiene un motivo de rechazo.

Una vez cumplida o rechazada, una promesa no puede cambiar de estado ni de resultado.

fulfilled significa que ha terminado correctamente. Una promesa rechazada también ha terminado, pero con un fallo.

2. Crear una promesa: resolve y reject

Utilizamos new Promise() y le pasamos una función que contiene las instrucciones para iniciar la operación. Esta función recibe otras dos funciones: resolve y reject.

Ejemplo de una promesa que se cumple con el número 5.

Creación de la promesa: 

let p1 = new Promise((resolve, reject) => {
  resolve(5);
});
Función Para qué se utiliza en estos ejemplos
resolve(valor) Completar correctamente la promesa con un valor.
reject(motivo) Rechazar la promesa e indicar el motivo.

La variable p1 guarda el objeto promesa. El número 5 es el resultado con el que esa promesa se cumple.

Aunque recibamos ambas funciones, no tenemos que utilizar las dos: llamamos a la que corresponda según lo ocurrido.

Ejemplo de una promesa que falla y proporciona un mensaje como motivo.

Rechazo de la promesa: 

let p3 = new Promise((resolve, reject) => {
  reject("La promesa NO se ha resuelto de forma correcta");
});

El texto es el motivo del rechazo. Más adelante podremos recibirlo y mostrarlo al gestionar el error.

Una promesa con espera

Este ejemplo utiliza un temporizador para simular una operación que tarda.

Promesa con setTimeout(): 

let p2 = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("La promesa se ha resuelto de forma correcta");
  }, 5000);
});

La promesa permanece pendiente hasta que se ejecuta resolve(). Los 5000 milisegundos representan una espera de unos cinco segundos; mientras tanto, el resto del programa puede continuar.

Crear una promesa no convierte automáticamente todo su contenido en asíncrono. La función que pasamos a new Promise() se ejecuta inmediatamente. Aquí, setTimeout() es lo que retrasa la llamada a resolve().

3. Recibir el resultado: .then(), .catch() y .finally()

Crear una promesa y utilizar su resultado son dos cosas diferentes.

Estos métodos permiten dejar preparadas las funciones que actuarán cuando la promesa termine.

Método Cuándo se ejecuta la función que recibe Para qué se utiliza
.then(valor => { ... }) Cuando la promesa se cumple. Trabajar con el resultado.
.catch(error => { ... }) Cuando le llega un rechazo desde los pasos anteriores de la cadena. Gestionar el error.
.finally(() => { ... }) Cuando termina el paso anterior, tanto con éxito como con rechazo. Realizar una acción final común.

Ejemplo adaptado, que utiliza la promesa p2 declarada en el apartado anterior.

Gestión del resultado y del error: 

p2
  .then((valor) => {
    console.log("OK:", valor);
  })
  .catch((error) => {
    console.log("Error:", error);
  })
  .finally(() => {
    console.log("Proceso terminado");
  });

Si p2 se cumple, su resultado llega al parámetro valor. Si se rechaza, el motivo llega a error.

Los nombres de estos parámetros los elegimos nosotros. Podríamos llamar resultado a valor y el comportamiento sería el mismo.

.finally() permite realizar una tarea común al terminar, como retirar un indicador de carga.

.finally() no recibe el resultado ni el motivo del rechazo. Para trabajar con ellos utilizamos .then() o .catch().

Otra sintaxis: las dos funciones de .then()

.then() también admite una segunda función para gestionar el rechazo de la promesa sobre la que se llama.

Este fragmento adapta los nombres de los parámetros del ejemplo original.

.then() con una función para el éxito y otra para el rechazo: 

p2.then(
  (valor) => console.log("OK:", valor),
  (error) => console.log("Error:", error)
);

La primera función atiende el éxito y la segunda el rechazo.

En cadenas de varios pasos, colocar un .catch() después permite centralizar la gestión de los errores que lleguen desde esos pasos.

4. Ampliación — Cuándo se ejecuta un .then()

Una promesa puede cumplirse inmediatamente, pero eso no hace que la función de su .then() se ejecute en ese mismo instante. Primero termina el código síncrono que está en marcha.

Ejemplo añadido para observar el orden de ejecución.

Código del ejemplo: 

console.log("1. Inicio");

let promesa = new Promise((resolve, reject) => {
  resolve(5);
});

promesa.then((valor) => {
  console.log("3. Resultado:", valor);
});

console.log("2. Fin del código síncrono");

Los mensajes aparecen en este orden: 

1. Inicio
2. Fin del código síncrono
3. Resultado: 5

Aunque el resultado 5 ya está disponible, la función del .then() queda programada para ejecutarse después del código síncrono actual.

Tener una promesa cumplida no significa que la función de su .then() se ejecute inmediatamente.

5. Encadenar promesas: para qué sirve return

Encadenar permite organizar varios pasos: recibir un resultado, trabajar con él y continuar con el siguiente.

Cada llamada a .then() devuelve una nueva promesa, lo que permite añadir otro .then().

Dentro de la función que pasamos a .then(), usamos return para decidir qué resultado entregamos al siguiente paso.

Devolver un valor

Ejemplo adaptado y simplificado para centrarnos en cómo se transmite el resultado: una promesa proporciona el número 5, lo multiplicamos por 2 y pasamos el resultado al siguiente paso.

Cadena que devuelve un valor: 

let p1 = new Promise((resolve, reject) => {
  resolve(5);
});

p1
  .then((numero) => {
    return numero * 2;
  })
  .then((resultado) => {
    console.log(resultado); // 10
  });

El primer .then() recibe 5, lo multiplica por 2 y devuelve 10. El siguiente .then() recibe ese 10.

El return de un .then() permite pasar un resultado al siguiente paso de la cadena.

Mostrar un valor no es lo mismo que devolverlo. console.log(numero * 2) lo muestra en la consola; return numero * 2 lo entrega como resultado de la función.

Devolver una promesa

Ejemplo adaptado a partir de las promesas del material. Después de recibir el resultado de p1, conectamos la cadena con el resultado de p2.

Cadena que devuelve una promesa. Este bloque incluye todas sus declaraciones: 

let p1 = new Promise((resolve, reject) => {
  resolve(5);
});

let p2 = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve(27);
  }, 2000);
});

p1
  .then((valor) => {
    console.log("Primer resultado:", valor);
    return p2;
  })
  .then((valor2) => {
    console.log("Segundo resultado:", valor2);
  })
  .catch((error) => {
    console.log("Ha ocurrido un error:", error);
  });

El primer .then() recibe 5 y devuelve p2. La cadena espera a que p2 termine, si todavía está pendiente. Cuando se cumple, el siguiente .then() recibe 27.

Si p2 se rechaza, se omite la función de éxito del siguiente .then() y el motivo llega a .catch().

Para entender la importancia de return, podemos comparar qué recibiría el segundo .then() si cambiásemos únicamente la línea return p2 del ejemplo:

Qué podría devolver el primer .then() Qué recibiría el segundo .then()
return valor Recibiría 5, porque valor contiene el resultado de p1.
return p2 Esperaría a p2 y recibiría 27 cuando se cumpla. Esta es la opción utilizada en el código.
No escribir return Recibiría undefined, porque la función del primer .then() no devuelve ningún valor.

En el código del ejemplo se utiliza return p2, por lo que el segundo .then() queda conectado a esa promesa y recibe su resultado: 27.

Si eliminamos return p2, la cadena deja de estar conectada a su resultado. El segundo .then() no espera a p2 ni recibe el 27.

Encadenar promesas ya creadas no retrasa el inicio de sus operaciones. En este ejemplo, el temporizador de p2 empieza al crearla; return p2 conecta la cadena con esa promesa.

6. Métodos estáticos: Promise.reject()

Un método estático se llama directamente sobre Promise, en lugar de sobre una promesa concreta.

Promise.reject(motivo) crea y devuelve una promesa que ya está rechazada.

Podemos utilizarlo dentro de un .then() cuando una condición no se cumple y queremos que la cadena continúe por la vía del error.

Las dos formas de rechazo utilizadas se diferencian en qué promesa rechazan:

Sintaxis Qué hace
reject(motivo) Rechaza la promesa que estamos creando con new Promise().
Promise.reject(motivo) Crea una nueva promesa que ya está rechazada.

Ejemplo: comprobar la edad y obtener una clave

Ejemplo del material: comprobamos una edad para decidir si la cadena continúa con la obtención de una clave o con un rechazo.

Primero se crean las dos promesas: 

let pp1 = new Promise((resolve, reject) => {
  resolve(18);
});

let pp2 = new Promise((resolve, reject) => {
  console.log("Generando clave");

  setTimeout(() => {
    resolve("aklhdgsi4");
  }, 5000);
});

Después se construye la cadena: 

pp1
  .then((edad) => {
    if (edad >= 18) {
      console.log("Acceso autorizado");
      return pp2;
    } else {
      return Promise.reject("Edad menor que 18");
    }
  })
  .then((clave) => {
    console.log("Tu clave es:", clave);
  })
  .catch((error) => {
    console.log("Ha ocurrido un error:", error);
  })
  .finally(() => {
    console.log("Cerrando la conexión");
  });

Con 18 años, se devuelve pp2. La cadena espera su resultado y después muestra la clave.

Si cambiamos resolve(18) por resolve(16), se devuelve una promesa rechazada. Se omite el .then() que muestra la clave y el motivo "Edad menor que 18" llega a .catch().

Si ejecutamos las declaraciones y la cadena juntas, el orden de los mensajes es:

Con 18 años Con 16 años
1. Generando clave 1. Generando clave
2. Acceso autorizado 2. Ha ocurrido un error: Edad menor que 18
3. Tras la espera: Tu clave es: aklhdgsi4 3. Cerrando la conexión
4. Cerrando la conexión

pp2 se crea antes de comprobar la edad. Por eso, "Generando clave" se muestra y el temporizador comienza en ambos casos. Si la edad es menor que 18, la cadena no espera a pp2, pero su temporizador sigue ejecutándose.

Este ejemplo sirve para entender el recorrido de la cadena. Para que la generación de la clave dependiera realmente de la edad, habría que iniciar esa operación dentro de la rama autorizada.

"Cerrando la conexión" solo es un mensaje de consola: el ejemplo no abre ni cierra una conexión real.
