Crear datos con POST y Fetch

Clase 40 · Enviar JSON a una API, crear tareas desde un formulario y cargar usuarios para seleccionarlos en una lista.

1. Objetivo de la clase

Hasta ahora habíamos utilizado fetch() principalmente para pedir información a una API mediante peticiones GET.

En esta clase damos el siguiente paso: enviar información desde JavaScript para crear un recurso nuevo.

El ejemplo consiste en crear una tarea en JSONPlaceholder: 

const URL_TODOS =
  "https://jsonplaceholder.typicode.com/todos";

Para crear un recurso mediante una API se utiliza normalmente una petición HTTP de tipo POST.

2. El método indica qué queremos hacer

Una misma API puede permitir varias operaciones. El método HTTP comunica al servidor qué acción queremos realizar.

Operación Método Ejemplo
Consultar GET GET /todos/1
Crear POST POST /todos
Modificar PUT PUT /todos/1
Borrar DELETE DELETE /todos/1

La dirección /todos representa la colección de tareas.

La dirección /todos/1 representa una tarea concreta, identificada con el número 1.

La URL identifica el recurso y el método HTTP indica la operación que queremos realizar sobre él.

3. El segundo argumento de fetch()

Si llamamos a fetch() solamente con una URL, se realiza una petición GET: 

fetch(URL_TODOS);

Para realizar un POST, añadimos un segundo argumento con la configuración de la petición: 

fetch(URL_TODOS, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    userId: 1,
    title: "Estudiar JavaScript",
    completed: false,
  }),
});
Propiedad Significado Por qué se utiliza
method Método HTTP de la petición Para indicar que queremos crear un recurso
headers Información adicional sobre la petición Para describir los datos enviados
Content-Type Formato del contenido Para indicar que enviamos JSON
body Cuerpo de la petición Para incluir los datos de la nueva tarea

El segundo argumento de fetch() describe cómo debe realizarse la petición.

4. El cuerpo de la petición

La información de la nueva tarea comienza siendo un objeto de JavaScript: 

const nuevaTarea = {
  userId: 1,
  title: "Estudiar JavaScript",
  completed: false,
};

Un objeto de JavaScript no se envía directamente en el cuerpo de la petición. Primero debemos convertirlo en una cadena JSON: 

const cuerpo = JSON.stringify(nuevaTarea);

Después colocamos esa cadena en la propiedad body: 

fetch(URL_TODOS, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify(nuevaTarea),
});

JSON.stringify() convierte un valor de JavaScript en una cadena con formato JSON.

El proceso puede representarse así: 

Objeto de JavaScript
        ↓
JSON.stringify()
        ↓
Cadena JSON
        ↓
body de la petición

JSON.stringify() no modifica el objeto original. Devuelve una cadena nueva.

5. Los encabezados de la petición

headers: {
  "Content-Type": "application/json",
}

Los encabezados aportan información sobre la petición.

En este caso, Content-Type comunica al servidor que el contenido de body está escrito en formato JSON.

Content-Type indica el formato de los datos que estamos enviando.

Enviar JSON en body y declarar Content-Type: application/json son dos pasos relacionados: uno prepara el contenido y el otro describe su formato.

6. Procesar la respuesta

fetch() devuelve una promesa. Cuando la petición recibe una respuesta, obtenemos un objeto Response. 

fetch(URL_TODOS, opciones)
  .then((response) => {
    if (!response.ok) {
      throw new Error(
        `Error HTTP: ${response.status}`
      );
    }

    return response.json();
  })
  .then((todoCreado) => {
    console.log(todoCreado);
  })
  .catch((error) => {
    console.log(error);
  });

Cada parte cumple una función diferente:

  1. fetch() realiza la petición.
  2. El primer .then() recibe el objeto Response.
  3. response.ok indica si la respuesta HTTP ha sido correcta.
  4. response.json() procesa el cuerpo de la respuesta.
  5. El segundo .then() recibe los datos convertidos a JavaScript.
  6. .catch() recibe los errores lanzados o los rechazos de la cadena.

response.json() devuelve una promesa con el contenido de la respuesta convertido a JavaScript.

Envío y recepción de JSON

Instrucción Dirección Función
JSON.stringify(datos) JavaScript → API Prepara los datos que enviamos
response.json() API → JavaScript Procesa los datos que recibimos

Aunque sus nombres se parecen, realizan operaciones contrarias.

7. JSONPlaceholder simula la creación

JSONPlaceholder permite practicar peticiones HTTP sin utilizar una base de datos propia.

Cuando recibe el POST, responde como si hubiese creado la tarea y devuelve los datos enviados junto con un identificador.

Una respuesta puede tener esta forma: 

{
  userId: 1,
  title: "Estudiar JavaScript",
  completed: false,
  id: 201
}

La creación es simulada. El recurso no queda almacenado permanentemente en la API.

Una respuesta correcta confirma que la petición se ha procesado, pero JSONPlaceholder no conserva realmente el nuevo recurso.

8. Formulario para crear una tarea

<form id="createTodo">
  <label for="userTodo">Usuario</label>

  <select id="userTodo" required>
    <option value="">Selecciona un usuario</option>
  </select>

  <label for="todoName">Nombre de la tarea</label>

  <input
    type="text"
    id="todoName"
    required
  >

  <input
    type="checkbox"
    id="todoCompleted"
  >

  <label for="todoCompleted">
    Completada
  </label>

  <button type="submit" id="saveTodo">
    Guardar
  </button>
</form>

Cada control representa una propiedad de la tarea que enviaremos.

Control Propiedad creada Dato obtenido
#userTodo userId Identificador del usuario
#todoName title Nombre de la tarea
#todoCompleted completed true o false

El botón tiene type="submit" porque su función es enviar el formulario.

Los campos obligatorios utilizan required, por lo que el navegador comprueba que estén completos antes de producir el envío válido.

9. Controlar el evento submit

const form =
  document.getElementById("createTodo");

form.addEventListener("submit", (event) => {
  event.preventDefault();

  // Crear y enviar la tarea
});

Escuchamos el evento submit porque representa el envío del formulario completo.

La función recibe un objeto event con información sobre lo sucedido. 

event.preventDefault();

Esta instrucción evita el comportamiento tradicional del formulario, que recargaría o cambiaría la página.

preventDefault() evita la acción predeterminada del formulario para que JavaScript pueda controlar el envío mediante fetch().

10. Leer los datos del formulario

const todoUser =
  document.getElementById("userTodo");

const todoName =
  document.getElementById("todoName");

const todoCompleted =
  document.getElementById("todoCompleted");

Estas constantes guardan referencias a los elementos HTML.

Para obtener los datos introducidos utilizamos sus propiedades: 

const nuevaTarea = {
  userId: Number(todoUser.value),
  title: todoName.value,
  completed: todoCompleted.checked,
};
Propiedad Resultado
.value Valor de un campo de texto o de una lista
.checked Estado booleano de un checkbox

Los valores de los controles HTML se obtienen como texto. Por eso convertimos el identificador del usuario con Number(): 

Number(todoUser.value);

Si todoUser.value contiene "3", el resultado será el número 3.

.value obtiene el valor de un control y .checked obtiene el estado de una casilla.

11. Informar de que la petición está en curso

saveTodo.disabled = true;
saveTodo.textContent = "Enviando...";

Mientras la petición está pendiente, desactivamos el botón para evitar varios envíos de la misma tarea.

También cambiamos su texto para informar al usuario.

Cuando la operación termina, restauramos el botón: 

.finally(() => {
  saveTodo.disabled = false;
  saveTodo.textContent = "Guardar";
});

finally() se ejecuta tanto si la promesa se resuelve como si se rechaza.

finally() permite restaurar la interfaz independientemente del resultado de la petición.

12. Enviar los datos del formulario

form.addEventListener("submit", (event) => {
  event.preventDefault();

  const nuevaTarea = {
    userId: Number(todoUser.value),
    title: todoName.value,
    completed: todoCompleted.checked,
  };

  saveTodo.disabled = true;
  saveTodo.textContent = "Enviando...";

  fetch(URL_TODOS, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(nuevaTarea),
  })
    .then((response) => {
      if (!response.ok) {
        throw new Error(
          `Error HTTP: ${response.status}`
        );
      }

      return response.json();
    })
    .then((todoCreado) => {
      console.log(todoCreado);
      form.reset();
    })
    .catch((error) => {
      console.log(error);
    })
    .finally(() => {
      saveTodo.disabled = false;
      saveTodo.textContent = "Guardar";
    });
});

El orden es importante:

  1. Evitamos la recarga de la página.
  2. Construimos el objeto con los valores actuales.
  3. Desactivamos el botón.
  4. Convertimos el objeto a JSON.
  5. Enviamos la petición POST.
  6. Procesamos la respuesta.
  7. Limpiamos el formulario si la operación termina correctamente.
  8. Restauramos el botón en todos los casos.

form.reset() devuelve todos los controles del formulario a sus valores iniciales.

El formulario se limpia únicamente después de recibir una respuesta correcta. Si ocurre un error, los datos permanecen visibles para que el usuario pueda intentarlo de nuevo.

13. Obtener los usuarios

Para que el usuario no tenga que escribir manualmente un identificador, obtenemos la lista de usuarios desde la API: 

const URL_USERS =
  "https://jsonplaceholder.typicode.com/users";

const cargarUsuarios = async () => {
  try {
    const response = await fetch(URL_USERS);

    if (!response.ok) {
      throw new Error(
        `Error HTTP: ${response.status}`
      );
    }

    const users = await response.json();

    // Crear las opciones
  } catch (error) {
    console.log(error);
  }
};

await fetch() espera a que llegue el objeto Response.

await response.json() espera a que el cuerpo de la respuesta se convierta en un array de usuarios. 

fetch()
   ↓
Response
   ↓
response.json()
   ↓
Array de usuarios

14. Crear las opciones dinámicamente

users.forEach((user) => {
  const option =
    document.createElement("option");

  option.value = user.id;
  option.textContent = user.name;

  todoUser.appendChild(option);
});

forEach() ejecuta la función una vez por cada usuario.

En cada vuelta:

  1. createElement() crea un elemento <option>.
  2. value guarda el identificador del usuario.
  3. textContent establece el nombre visible.
  4. appendChild() añade la opción al <select>.

Si recibimos este usuario: 

{
  id: 1,
  name: "Leanne Graham"
}

Se crea un elemento equivalente a: 

<option value="1">
  Leanne Graham
</option>

El identificador se utiliza como valor de la opción y el nombre se muestra al usuario.

Código completo

const URL_TODOS =
  "https://jsonplaceholder.typicode.com/todos";

const URL_USERS =
  "https://jsonplaceholder.typicode.com/users";

const form =
  document.getElementById("createTodo");

const todoUser =
  document.getElementById("userTodo");

const todoName =
  document.getElementById("todoName");

const todoCompleted =
  document.getElementById("todoCompleted");

const saveTodo =
  document.getElementById("saveTodo");

const cargarUsuarios = async () => {
  try {
    const response = await fetch(URL_USERS);

    if (!response.ok) {
      throw new Error(
        `Error HTTP: ${response.status}`
      );
    }

    const users = await response.json();

    users.forEach((user) => {
      const option =
        document.createElement("option");

      option.value = user.id;
      option.textContent = user.name;

      todoUser.appendChild(option);
    });
  } catch (error) {
    console.log(error);
  }
};

form.addEventListener("submit", (event) => {
  event.preventDefault();

  const nuevaTarea = {
    userId: Number(todoUser.value),
    title: todoName.value,
    completed: todoCompleted.checked,
  };

  saveTodo.disabled = true;
  saveTodo.textContent = "Enviando...";

  fetch(URL_TODOS, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(nuevaTarea),
  })
    .then((response) => {
      if (!response.ok) {
        throw new Error(
          `Error HTTP: ${response.status}`
        );
      }

      return response.json();
    })
    .then((todoCreado) => {
      console.log(todoCreado);
      form.reset();
    })
    .catch((error) => {
      console.log(error);
    })
    .finally(() => {
      saveTodo.disabled = false;
      saveTodo.textContent = "Guardar";
    });
});

cargarUsuarios();

Ideas esenciales

GET solicita información y POST envía datos para crear un recurso.

El segundo argumento de fetch() contiene la configuración de la petición.

method: "POST" indica que queremos crear un recurso.

Content-Type: application/json describe el formato del contenido enviado.

JSON.stringify() convierte un valor de JavaScript en una cadena JSON.

response.json() procesa el JSON recibido y devuelve una promesa.

El evento submit permite controlar el envío completo de un formulario.

preventDefault() evita la recarga para que JavaScript gestione el envío.

.value permite leer campos de texto y listas, mientras que .checked permite leer un checkbox.

createElement() crea un elemento del DOM y appendChild() lo añade al documento.

Una interfaz debe informar al usuario mientras una operación asíncrona está pendiente.
