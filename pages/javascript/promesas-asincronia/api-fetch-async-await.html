API, Fetch, Async y Await

Clase 39 · Consultar APIs, procesar respuestas HTTP y trabajar con promesas mediante fetch, async y await.

1. ¿Qué es una API?

Cuando una aplicación necesita información que se encuentra en otro sistema, puede comunicarse con él mediante una API.

Una API es un conjunto de reglas y direcciones que permite que distintas aplicaciones intercambien datos.

Por ejemplo, una aplicación puede pedir a un servidor:

  • La información de un usuario.
  • Una lista de coches.
  • Los datos de una publicación.

Cada dirección disponible dentro de una API se denomina endpoint. Normalmente, combina la dirección base de la API con la ruta del recurso que queremos utilizar. 

https://jsonplaceholder.typicode.com/users/1

En este ejemplo:

  • https://jsonplaceholder.typicode.com es la dirección base de la API.
  • /users/1 solicita el usuario cuyo identificador es 1.

2. Operaciones habituales de una API

Para indicar qué queremos hacer con un recurso se utilizan métodos HTTP.

Operación Método Ejemplo de ruta
Consultar información GET /todos/1
Crear un recurso POST /todos
Modificar un recurso PUT /todos/1
Borrar un recurso DELETE /todos/1

En esta clase se trabaja con peticiones de consulta, es decir, con GET.

3. Fetch

fetch() permite pedir o enviar datos a un servidor desde JavaScript.

Para hacer una petición, le pasamos la URL a la que queremos acceder: 

const URL = "https://jsonplaceholder.typicode.com/users/1";

fetch(URL);

fetch(URL) inicia la petición y devuelve inmediatamente una promesa. Los datos no se reciben en ese mismo instante: hay que esperar a que el servidor responda.

La sintaxis general de fetch() permite pasarle dos argumentos: 

fetch(url, opciones);
Argumento Significado
url Dirección a la que se realiza la petición.
opciones Objeto opcional con la configuración de la petición.

La URL es obligatoria, pero el objeto de opciones es opcional.

El objeto de opciones permite especificar aspectos como el método HTTP o los datos que queremos enviar. En el primer ejemplo no hace falta utilizarlo porque fetch() realiza una petición GET de manera predeterminada.

4. Procesar la respuesta con promesas

Como fetch() devuelve una promesa, podemos trabajar con los métodos ya conocidos:

  • .then() para procesar el resultado.
  • .catch() para capturar un rechazo.
  • .finally() si necesitamos ejecutar algo al terminar, independientemente del resultado. 
fetch(URL)
  .then((response) => {
    console.log(response);
  })
  .catch((error) => {
    console.log(error);
  });

El primer .then() no recibe directamente los datos solicitados: recibe un objeto Response.

Este objeto contiene información sobre la respuesta HTTP, como su estado y si la petición ha obtenido una respuesta considerada correcta.

5. Comprobar response.ok

La propiedad response.ok indica si la respuesta HTTP se considera correcta. 

fetch(URL)
  .then((response) => {
    if (response.ok) {
      return response.json();
    }

    return Promise.reject(
      "No se ha encontrado el usuario con ese identificador"
    );
  })
  .then((user) => console.log(user))
  .catch((error) => console.log(error));

El recorrido de este ejemplo es el siguiente:

  1. fetch(URL) realiza la petición.
  2. El primer .then() recibe el objeto Response.
  3. Si response.ok es true, se procesa el cuerpo de la respuesta.
  4. Si response.ok es false, se devuelve una promesa rechazada.
  5. El segundo .then() recibe los datos ya convertidos.
  6. .catch() recibe cualquier rechazo producido durante la cadena.

fetch() no rechaza automáticamente la promesa solo porque el servidor responda con un error HTTP, como 404 o 500.

Una respuesta HTTP con error puede llegar al .then(), por lo que debemos comprobar response.ok.

fetch() sí puede rechazar la promesa si la petición no llega a completarse, por ejemplo, debido a un problema de red.

6. Convertir la respuesta con response.json()

El objeto Response no contiene directamente un objeto de JavaScript preparado para utilizarse. Para obtener los datos del cuerpo de la respuesta usamos: 

response.json();

response.json() lee el cuerpo de la respuesta, lo interpreta como JSON y devuelve otra promesa.

Por eso se devuelve su resultado desde el primer .then(): 

return response.json();

Al devolver esa promesa, el siguiente .then() espera a que se resuelva y recibe los datos convertidos: 

.then((user) => console.log(user))

El recorrido completo puede representarse así: 

fetch()
   ↓
objeto Response
   ↓
response.json()
   ↓
datos de JavaScript

response.json() no es una propiedad que ya contenga los datos. Es un método asíncrono y debemos ejecutarlo utilizando paréntesis.

7. Funciones async y uso de await

La palabra async permite declarar una función asíncrona. 

const getUser = async () => {
  // Operaciones asíncronas
};

Una función declarada con async siempre devuelve una promesa.

Dentro de una función async podemos utilizar await para esperar la resolución de una promesa. 

const getUser = async () => {
  const response = await fetch(URL);
};

En este ejemplo, await espera a que se resuelva la promesa devuelta por fetch(URL). Cuando se resuelve, su resultado se guarda en response.

await pausa la ejecución de la función async en la que se encuentra, pero no bloquea todo JavaScript.

Mientras esa función espera, el resto del programa puede seguir ejecutándose.

Normalmente, await debe utilizarse dentro de una función declarada con async.

8. Relación entre las promesas, .then() y await

.then() y await permiten esperar y procesar promesas, pero organizan el código de manera diferente.

Utilizando .then()

fetch(URL)
  .then((response) => response.json())
  .then((user) => console.log(user));

Utilizando async y await

const getUser = async () => {
  const response = await fetch(URL);
  const user = await response.json();

  console.log(user);
};

getUser();

La versión con async y await se puede leer de arriba abajo:

  1. Se espera la respuesta del servidor.
  2. Se espera la conversión del cuerpo a JSON.
  3. Se muestran los datos del usuario.

async y await no sustituyen a las promesas: proporcionan otra sintaxis para trabajar con ellas.

Aunque visualmente el código parezca síncrono, las operaciones siguen siendo asíncronas y continúan basándose en promesas.

Esta forma de escribir el código evita tener que encadenar continuamente .then() y ayuda a que las operaciones asíncronas resulten más fáciles de seguir.

9. Obtener una lista de coches y filtrarla

La API utilizada devuelve un objeto que contiene una propiedad cars. Esta propiedad almacena el array de coches. 

const URLCARS = "https://myfakeapi.com/api/cars/";

La función recibe el año por el que queremos filtrar. Si no proporcionamos ninguno, utiliza 2010 como valor predeterminado. 

const getCars = async (year = 2010) => {
  const cars = await fetch(URLCARS)
    .then((response) => response.json())
    .then((data) =>
      data["cars"].filter(
        (car) => car.car_model_year === year
      )
    );

  console.log(cars);
};

getCars(2011);

En este ejemplo, await espera el resultado final de toda la cadena formada por fetch() y los dos .then().

El parámetro year = 2010 tiene un valor predeterminado:

  • getCars() filtra los coches del año 2010.
  • getCars(2011) filtra los coches del año 2011.

Esta expresión accede a la propiedad que contiene el array: 

data["cars"]

Después, .filter() recorre ese array y conserva únicamente los coches que cumplen la condición: 

.filter((car) => car.car_model_year === year)

En cada vuelta:

  • car representa el coche que se está comprobando.
  • car.car_model_year accede al año de ese coche.
  • car.car_model_year === year comprueba si coincide con el año solicitado.

10. Peticiones consecutivas con await

También podemos realizar varias operaciones asíncronas de manera consecutiva.

En el siguiente ejemplo, primero se obtiene el año del primer coche. Después, ese año se utiliza para filtrar todos los coches que coinciden con él. 

const getCarsFromFirstCarYear = async () => {
  const firstCarYear = await fetch(URLCARS)
    .then((response) => response.json())
    .then((data) => data["cars"][0].car_model_year);

  const allCarsFilterByYear = await fetch(URLCARS)
    .then((response) => response.json())
    .then((data) =>
      data["cars"].filter(
        (car) => car.car_model_year === firstCarYear
      )
    );

  console.log(allCarsFilterByYear);
};

getCarsFromFirstCarYear();

La primera cadena obtiene el año del primer coche: 

data["cars"][0].car_model_year

El acceso se realiza por niveles:

Expresión Resultado
data Objeto completo obtenido de la API.
data["cars"] Array de coches.
data["cars"][0] Primer coche del array.
data["cars"][0].car_model_year Año del primer coche.

Ese año se guarda en la variable: 

const firstCarYear = ...

Después, la segunda petición vuelve a obtener los coches y filtra los que tienen ese mismo año: 

car.car_model_year === firstCarYear

Las dos operaciones se ejecutan de manera secuencial: primero termina la que obtiene el año y después continúa la que realiza el filtro.

El primer await debe obtener el año antes de que el código pueda utilizarlo en la segunda operación.

11. Legibilidad del código asíncrono

Cuando un programa contiene muchas operaciones asíncronas, puede acumular numerosos .then() o callbacks anidados y resultar más difícil de leer.

async y await permiten organizar esas operaciones en un orden más próximo a la forma en la que razonamos: 

const response = await fetch(URL);
const data = await response.json();

console.log(data);

Aunque las instrucciones se lean de arriba abajo, no dejan de ser operaciones asíncronas.

await espera el resultado dentro de la función, pero no congela la ejecución completa del programa.

12. Ideas esenciales de la clase

Una API permite que distintas aplicaciones intercambien datos.

Los métodos HTTP indican qué operación queremos realizar sobre un recurso.

fetch() inicia una petición y devuelve una promesa.

La URL es obligatoria y el objeto de opciones es opcional.

El primer resultado de fetch() es un objeto Response, no los datos convertidos.

response.json() procesa el cuerpo JSON y también devuelve una promesa.

Un error HTTP no rechaza automáticamente fetch(); debemos comprobar response.ok.

Una función declarada con async siempre devuelve una promesa.

await pausa la función asíncrona actual mientras espera la resolución de una promesa.

async y await ofrecen una sintaxis más secuencial y legible para trabajar con promesas.
