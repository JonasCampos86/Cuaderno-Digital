Promesas en serie y métodos de coordinación

Clase 38 · Encadenar operaciones dependientes, coordinar resultados y utilizar funciones que reciben argumentos y devuelven promesas.

1. Organizar varias operaciones asíncronas

Cuando necesitamos realizar varias operaciones asíncronas, debemos decidir si unas dependen de otras o si pueden ejecutarse de forma independiente.

Organización Cuándo se utiliza
En serie Cuando una operación necesita el resultado de la anterior.
En paralelo Cuando las operaciones son independientes y queremos coordinar sus resultados.

Por ejemplo:

  • Para consultar la actividad de un usuario, primero necesitamos encontrar al usuario. Son operaciones dependientes.
  • Para solicitar datos independientes a varios servidores, podemos iniciar todas las operaciones y coordinar sus resultados.

Si una operación necesita el resultado de otra, debemos iniciarla después de recibir ese resultado.

2. Promesas y valores utilizados en los ejemplos

Creación de las promesas y del valor: 

const promise1 = Promise.reject(55);

const promise2 = 33;

const promise3 = new Promise((resolve, reject) => {
  setTimeout(resolve, 1000, "Se ha ejecutado la promesa 3");
});
Elemento Qué contiene
promise1 Una promesa ya rechazada cuyo motivo es 55.
promise2 El valor normal 33; no es una promesa.
promise3 Una promesa que se cumple aproximadamente un segundo después con el texto "Se ha ejecutado la promesa 3".

La sintaxis utilizada en el temporizador equivale a llamar a resolve() después de un segundo pasándole el texto como argumento: 

setTimeout(() => {
  resolve("Se ha ejecutado la promesa 3");
}, 1000);

Métodos como Promise.all() también pueden recibir valores normales. El valor 33 se trata como un resultado cumplido.

promise1 y promise3 comienzan al crearse. Añadirlas posteriormente a una cadena o a un método estático no inicia sus operaciones: únicamente conecta o coordina sus resultados.

3. Promesas en serie

Utilizamos una cadena cuando el siguiente paso debe trabajar con el resultado del anterior.

Encadenamiento de los resultados: 

promise1
  .then((valor) => {
    console.log("valor", valor);
    return promise2;
  })
  .then((valor2) => {
    console.log("valor2", valor2);
    return promise3;
  })
  .then((valor3) => {
    console.log("valor3", valor3);
  })
  .catch((error) => {
    console.error("Error", error);
  })
  .finally(() => {
    console.log("Finally");
  });

Recorrido cuando promise1 está rechazada

promise1 está rechazada con 55. Por tanto, las funciones de éxito de los tres .then() se omiten hasta encontrar .catch().

La salida es:

Error 55
Finally

.catch() recibe el motivo 55 y .finally() se ejecuta al terminar la cadena.

Recorrido cuando promise1 se cumple

Ejemplo adaptado para observar el recorrido de éxito. Cambiamos únicamente la declaración de promise1: 

const promise1 = Promise.resolve(55);

La cadena seguiría estos pasos:

  1. El primer .then() recibe 55, lo muestra y devuelve promise2.
  2. Como promise2 contiene el valor normal 33, el segundo .then() recibe 33.
  3. El segundo .then() devuelve promise3.
  4. Si promise3 continúa pendiente, la cadena espera hasta que se cumpla.
  5. El tercer .then() recibe "Se ha ejecutado la promesa 3".
  6. Como no hay ningún rechazo, .catch() se omite.
  7. Finalmente se ejecuta .finally().

La salida sería:

valor 55
valor2 33
valor3 Se ha ejecutado la promesa 3
Finally

Devolver una promesa conecta la cadena con su resultado; devolver un valor normal entrega ese valor al siguiente .then().

En este ejemplo, promise3 ya fue creada y su temporizador ya empezó. La cadena procesa los resultados en orden, pero no provoca que todas las operaciones comiencen en ese orden.

4. Coordinar operaciones independientes

Los métodos estáticos permiten coordinar varias promesas y valores mediante una única llamada.

Sintaxis general:

Promise.metodo([promesa1, promesa2, promesa3]);

En esta clase se utilizan cuatro métodos:

  • Promise.all()
  • Promise.race()
  • Promise.any()
  • Promise.allSettled()

Estos métodos no ponen en marcha las promesas recibidas. Las promesas creadas anteriormente ya han comenzado; los métodos coordinan sus resultados.

5. Promise.all(): necesitamos todos los resultados

Promise.all() espera a que todos sus elementos se cumplan. Cuando lo consigue, devuelve un array con todos los resultados.

Si cualquiera de las promesas se rechaza, Promise.all() también se rechaza.

Coordinación de todos los resultados: 

Promise.all([promise1, promise2, promise3])
  .then((valoresRetornados) => {
    console.log(valoresRetornados);
  })
  .catch((error) => {
    console.error("Alguna promesa ha sido rechazada", error);
  });

Resultado cuando una promesa se rechaza

promise1 ya está rechazada con 55. Por tanto, Promise.all() también se rechaza y el motivo llega a .catch().

La salida es:

Alguna promesa ha sido rechazada 55

Resultado cuando todas se cumplen

Ejemplo adaptado para comprobar el resultado conjunto. Cambiamos promise1 por una promesa cumplida: 

const promise1 = Promise.resolve(55);

Promise.all() espera a promise3 y después devuelve: 

[
  55,
  33,
  "Se ha ejecutado la promesa 3"
]

Los resultados conservan el orden de entrada, aunque las promesas no terminen en ese mismo orden.

Si una promesa provoca el rechazo de Promise.all(), las demás operaciones no se cancelan automáticamente; pueden continuar ejecutándose aunque su resultado ya no se utilice en ese Promise.all().

6. Promise.race(): importa la primera que termine

Promise.race() observa todas las promesas y toma el resultado de la primera que termine.

La primera promesa que se cumpla o se rechace determina el resultado de Promise.race().

Carrera entre los resultados: 

Promise.race([promise1, promise2, promise3])
  .then((valor) => {
    console.log("Race", valor);
  })
  .catch((error) => {
    console.error("Error", error);
  });

Con las declaraciones iniciales, promise1 ya está rechazada. Al ser el primer resultado atendido por la carrera, Promise.race() se rechaza con 55.

La salida es:

Error 55

No debemos definir Promise.race() como «la primera promesa que se resuelve correctamente». También puede ganar un rechazo.

Aunque una promesa gane la carrera, las demás no se cancelan automáticamente.

7. Promise.any(): necesitamos el primer éxito

Promise.any() busca la primera promesa que se cumpla correctamente.

Los rechazos se ignoran mientras todavía exista otra operación que pueda cumplirse.

Obtención del primer resultado correcto: 

Promise.any([promise1, promise2, promise3])
  .then((valor) => {
    console.log("Any", valor);
  })
  .catch((error) => {
    console.error("Error", error);
  });

Con las declaraciones iniciales:

  1. promise1 está rechazada con 55, por lo que Promise.any() ignora ese rechazo.
  2. promise2 contiene el valor cumplido 33.
  3. Promise.any() se cumple con 33 sin necesitar esperar el resultado de promise3.

La salida es:

Any 33

Si todas las promesas se rechazan, Promise.any() también se rechaza y el error llega a .catch().

8. Promise.allSettled(): conocer todos los resultados

Promise.allSettled() espera hasta que todos los elementos hayan terminado, tanto si se cumplen como si se rechazan.

Comprobación del estado de todas las operaciones: 

Promise.allSettled([promise1, promise2, promise3])
  .then((valores) => {
    console.log("allSettled", valores);
  });

Los rechazos individuales no provocan el rechazo de Promise.allSettled(). Cada resultado aparece descrito dentro del array final.

Con las declaraciones iniciales, el resultado tiene esta estructura: 

[
  {
    status: "rejected",
    reason: 55
  },
  {
    status: "fulfilled",
    value: 33
  },
  {
    status: "fulfilled",
    value: "Se ha ejecutado la promesa 3"
  }
]
Propiedad Cuándo aparece Qué contiene
status En todos los resultados. "fulfilled" o "rejected".
value Cuando el resultado se ha cumplido. El valor obtenido.
reason Cuando el resultado se ha rechazado. El motivo del rechazo.

Promise.allSettled() permite inspeccionar todos los éxitos y todos los fallos sin detenerse al encontrar el primer rechazo.

Decir que Promise.allSettled() «no ejecuta .catch()» es demasiado absoluto. Lo correcto es que el rechazo de una de las promesas recibidas se incluye en el array de resultados y no rechaza por sí solo el Promise.allSettled().

9. Diferencias entre los métodos estáticos

Método Cuándo termina Qué sucede ante un rechazo
Promise.all() Cuando todas se cumplen o cuando aparece el primer rechazo. Un solo rechazo hace que el resultado conjunto se rechace.
Promise.race() Cuando termina la primera, sea éxito o rechazo. Si el primer resultado es un rechazo, la carrera se rechaza.
Promise.any() Cuando encuentra el primer resultado cumplido. Ignora los rechazos mientras pueda encontrar un éxito; se rechaza si todas fallan.
Promise.allSettled() Cuando todas han terminado. Incluye cada rechazo en el array mediante status y reason.

La pregunta que diferencia los métodos es qué resultados necesitamos:

Necesidad Método
Necesito que todas salgan bien. Promise.all()
Necesito el primer resultado que termine, sea bueno o malo. Promise.race()
Necesito el primer resultado correcto. Promise.any()
Necesito saber cómo ha terminado cada operación. Promise.allSettled()

10. Funciones que reciben argumentos y devuelven promesas

Crear una promesa directamente hace que su función comience a ejecutarse en ese momento. Si queremos decidir cuándo empieza la operación, podemos crear una función que devuelva una promesa.

Declarar una función que devuelve una promesa no inicia la operación; la promesa se crea cuando llamamos a la función.

Buscar un usuario

El ejemplo simula una búsqueda mediante el nombre recibido como argumento.

Función que busca un usuario: 

const buscarUsuario = (nombre) =>
  new Promise((resolve, reject) => {
    console.log("Buscando un usuario con el nombre:", nombre);

    let user = {
      name: "Antonio Pérez",
      dni: 12345678,
      edad: 19
    };

    resolve(user);
  });

buscarUsuario guarda una función. La promesa no se crea hasta que llamamos, por ejemplo, a: 

buscarUsuario("Antonio");

El argumento "Antonio" llega al parámetro nombre. La promesa se cumple con el objeto user.

La búsqueda está simulada: el objeto se encuentra escrito directamente en el código y no se consulta ningún servidor real.

Buscar la actividad del usuario

Esta segunda función recibe el usuario encontrado y una fecha, y devuelve una promesa con sus actividades.

Función que construye la actividad del usuario: 

const buscarActividad = (user, fechaActual) =>
  new Promise((resolve, reject) => {
    const actions = {
      user: user,
      activities: [
        {
          date: fechaActual,
          text: "entrar"
        },
        {
          date: fechaActual,
          text: "nadar"
        },
        {
          date: fechaActual,
          text: "caminar"
        }
      ]
    };

    resolve(actions);
  });

El resultado contiene dos propiedades:

Propiedad Contenido
user El objeto del usuario recibido como argumento.
activities Un array con las actividades asociadas a la fecha recibida.

11. Encadenar operaciones que dependen entre sí

No podemos buscar la actividad concreta hasta obtener primero el usuario. Por eso llamamos a buscarActividad() dentro del .then() que recibe ese usuario.

Búsqueda encadenada del usuario y su actividad: 

buscarUsuario("Antonio")
  .then((user) => {
    console.log("El usuario que se ha encontrado es:", user);
    return buscarActividad(user, new Date());
  })
  .then((activities) => {
    console.log(activities);
  });

El recorrido es:

  1. Se llama a buscarUsuario("Antonio") y en ese momento se crea la primera promesa.
  2. La primera promesa se cumple con el objeto user.
  3. El primer .then() recibe ese usuario.
  4. Se llama a buscarActividad(user, new Date()) y en ese momento se crea la segunda promesa.
  5. return conecta la cadena con la segunda promesa.
  6. El segundo .then() espera y recibe el objeto actions.

La segunda operación comienza dentro del primer .then() porque necesita el usuario obtenido en el paso anterior.

new Date() crea un objeto con la fecha y la hora actuales y se entrega como argumento a buscarActividad().

El parámetro activities del último .then() recibe realmente el objeto completo actions, que contiene tanto user como activities. Un nombre como resultadoActividad describiría el valor con mayor precisión.

La cadena del ejemplo no incluye .catch(). Las dos funciones simuladas siempre llaman a resolve(), pero una operación real que pudiera rechazarse debería gestionar ese rechazo.
