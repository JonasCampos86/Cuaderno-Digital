Introducción a las bases de datos y MySQL

Clase 1 · Organizar información, relacionar tablas y distinguir el lenguaje SQL, el gestor MySQL y la herramienta MySQL Workbench.

1. ¿Qué es una base de datos?

Una base de datos es un conjunto organizado de datos que permite almacenar información, consultarla y mantenerla actualizada.

Una tienda puede guardar información sobre sus clientes, productos y pedidos. Una aplicación de reservas puede almacenar usuarios, alojamientos y fechas disponibles.

Lo importante no es solamente guardar datos. También necesitamos encontrarlos, relacionarlos y modificarlos de forma controlada.

Necesidad Qué aporta una base de datos
Organización Estructura la información para facilitar su gestión.
Consulta Permite localizar datos mediante diferentes condiciones.
Integridad Permite establecer reglas para mantener datos válidos y coherentes.
Seguridad Permite controlar quién puede acceder a los datos y qué operaciones puede realizar.

Una base de datos no evita automáticamente los datos duplicados o incorrectos. Para conseguirlo también necesitamos diseñarla correctamente y establecer las reglas adecuadas.

2. Bases de datos relacionales

Una base de datos relacional organiza la información en tablas que pueden relacionarse entre sí.

2.1. Tabla, columna y fila

Imaginemos una tabla llamada clientes:

id nombre
1 Ana
2 Luis
  • Tabla: organiza datos de una misma clase. En este ejemplo contiene clientes.
  • Columna: representa una característica de los datos, como el identificador o el nombre.
  • Fila o registro: reúne toda la información de un elemento concreto.
  • Base de datos: contiene las tablas y otros elementos necesarios para organizar la información.

La primera fila representa a Ana. Su id es 1 y su nombre es "Ana".

Una base de datos puede contener varias tablas; cada tabla contiene filas y cada fila está formada por columnas.

2.2. El esquema de una tabla

El esquema define la estructura que deben respetar los datos de una tabla.

En él se establecen sus columnas, los tipos de datos que admite cada una y las reglas que deben cumplirse.

Podemos establecer que:

  • id almacene números enteros.
  • nombre almacene texto.
  • Cada cliente tenga un identificador diferente.

Un esquema definido no significa que la estructura nunca pueda cambiar. Significa que los datos deben respetar la estructura establecida en ese momento.

2.3. Claves y relaciones

Añadimos una tabla llamada pedidos:

id cliente_id producto
101 1 Teclado
102 1 Ratón
103 2 Monitor

El valor de cliente_id indica qué cliente ha realizado cada pedido.

Los pedidos 101 y 102 pertenecen a Ana porque contienen el valor 1, que coincide con su identificador en la tabla clientes.

Una clave es una columna, o un conjunto de columnas, utilizada para identificar filas o establecer relaciones entre tablas.

Clave Función
PRIMARY KEY La clave primaria identifica de forma única cada fila de una tabla.
FOREIGN KEY La clave foránea guarda una referencia a una fila de otra tabla.

En este ejemplo:

  • clientes.id es la clave primaria de la tabla clientes.
  • pedidos.cliente_id es una clave foránea que hace referencia a clientes.id.

Una relación conecta filas de diferentes tablas mediante valores que hacen referencia unos a otros.

Gracias a esta relación, cada pedido solo necesita guardar el identificador del cliente. No necesita repetir también su nombre.

3. Una primera muestra de SQL

Las siguientes instrucciones crean la estructura de las tablas anteriores: 

CREATE TABLE clientes (
    id INT PRIMARY KEY,
    nombre VARCHAR(50)
);

CREATE TABLE pedidos (
    id INT PRIMARY KEY,
    cliente_id INT,
    producto VARCHAR(50),
    FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);
Sintaxis Significado
CREATE TABLE Crea una tabla.
INT Indica que la columna almacena números enteros.
VARCHAR(50) Indica que la columna almacena texto de longitud variable, con un máximo de 50 caracteres.
PRIMARY KEY Define la clave primaria de la tabla.
FOREIGN KEY Define una clave foránea.
REFERENCES Indica la tabla y la columna a las que hace referencia la clave foránea.

Primero se crea clientes porque la tabla pedidos necesita hacer referencia a ella.

El resultado son dos tablas vacías con su estructura definida.

Estas instrucciones crean las tablas, pero todavía no introducen las filas de Ana, Luis y sus pedidos.

4. Bases de datos no relacionales

Las bases de datos no relacionales utilizan modelos diferentes al formado por tablas relacionadas.

Pueden organizar la información mediante documentos, pares clave-valor, grafos u otros modelos.

Una base de datos orientada a documentos podría representar a Ana y sus pedidos de esta manera: 

{
  "id": 1,
  "nombre": "Ana",
  "pedidos": [
    {
      "id": 101,
      "producto": "Teclado"
    },
    {
      "id": 102,
      "producto": "Ratón"
    }
  ]
}

En este ejemplo, los pedidos están incluidos dentro del documento del cliente, en lugar de guardarse en una tabla separada.

JSON es un formato utilizado para representar datos. Este ejemplo no es una consulta SQL.

Muchas bases de datos no relacionales ofrecen una estructura flexible, por lo que diferentes documentos pueden contener campos distintos.

NoSQL no significa que los datos carezcan de estructura o de reglas. La forma de organizarlos depende del sistema utilizado.

5. Bases de datos relacionales y no relacionales

Aspecto Bases relacionales Bases no relacionales
Organización Tablas formadas por filas y columnas. Documentos, clave-valor, grafos u otros modelos.
Estructura Esquema definido con tipos de datos y reglas. Generalmente ofrecen una estructura más flexible.
Relaciones Conectan tablas mediante claves. Dependen del modelo utilizado.
Lenguaje Utilizan SQL, aunque existen diferencias entre motores. Utilizan lenguajes de consulta o APIs propios de cada sistema.
Ejemplos MySQL, PostgreSQL y SQLite. MongoDB.

5.1. ¿Cuál debemos elegir?

Una base de datos relacional suele ser adecuada cuando los datos tienen una estructura predecible, existen relaciones claras y necesitamos mantener su coherencia.

Algunos ejemplos son la gestión de clientes y pedidos, la contabilidad o un sistema de reservas.

Una base de datos no relacional puede ser adecuada cuando el modelo de documentos, grafos o clave-valor encaja mejor con la información y con la manera de consultarla.

Algunos ejemplos son los documentos con campos variables, las redes de relaciones o determinados sistemas que manejan grandes cantidades de eventos.

La elección depende de las necesidades del proyecto; ningún modelo es siempre mejor que el otro.

5.2. ¿Qué significa escalar?

Escalar significa aumentar la capacidad de un sistema para soportar más datos, usuarios o trabajo.

  • Escalado vertical: aumentar los recursos de una máquina.
  • Escalado horizontal: repartir el trabajo entre varias máquinas.

Aunque determinados sistemas favorezcan una forma de escalado, la capacidad real depende del motor, de su configuración y de la arquitectura utilizada.

6. ¿Qué es MySQL?

MySQL es un sistema gestor de bases de datos relacionales.

Es el programa encargado de crear y administrar las bases de datos, almacenar su información y procesar las instrucciones SQL.

Un sistema gestor de bases de datos también puede denominarse SGBD.

En inglés se utiliza RDBMS, que significa Relational Database Management System.

La base de datos contiene la información; MySQL es el programa que la gestiona.

6.1. Características principales de MySQL

Característica Explicación
Código abierto Dispone de una edición comunitaria gratuita y de ediciones comerciales.
Rendimiento Está preparado para gestionar consultas y cantidades importantes de datos.
Seguridad Permite administrar usuarios, contraseñas y permisos.
Multiplataforma Puede utilizarse en diferentes sistemas operativos y entornos.
Uso de SQL Procesa instrucciones escritas en SQL e incorpora algunas características propias.
Uso habitual Es ampliamente utilizado en aplicaciones web y sistemas de gestión.

El rendimiento y la seguridad no dependen únicamente del gestor. También influyen el diseño de la base de datos, las consultas y la configuración del sistema.

7. MySQL y otras alternativas

Sistema Tipo Característica principal
MySQL Relacional Muy utilizado en aplicaciones web y sistemas de gestión.
PostgreSQL Relacional Destaca por sus numerosas funciones y posibilidades de ampliación.
SQLite Relacional Se integra dentro de la aplicación y no necesita un servidor independiente.
MongoDB No relacional Organiza la información mediante documentos flexibles.

No existe un motor adecuado para todos los proyectos. Cada uno resuelve necesidades diferentes.

8. SQL, MySQL y MySQL Workbench

Aunque están relacionados, SQL, MySQL y MySQL Workbench no son lo mismo.

Elemento Qué es Para qué se utiliza
SQL Un lenguaje. Permite dar instrucciones para crear estructuras, consultar datos y modificarlos.
MySQL Un sistema gestor de bases de datos. Almacena los datos y procesa las instrucciones SQL.
MySQL Workbench Una herramienta gráfica. Facilita la conexión con MySQL y permite escribir, ejecutar y visualizar consultas.

SQL es el lenguaje, MySQL es el gestor y MySQL Workbench es una herramienta para trabajar con ese gestor.

8.1. Flujo de funcionamiento

Cuando ejecutamos una instrucción desde MySQL Workbench, ocurre este proceso:

  1. Escribimos una instrucción utilizando el lenguaje SQL.
  2. MySQL Workbench envía la instrucción al servidor MySQL.
  3. MySQL procesa la instrucción y trabaja con la base de datos.
  4. MySQL devuelve el resultado o un mensaje de error.
  5. MySQL Workbench muestra la respuesta en pantalla.

El servidor MySQL es el programa que recibe y procesa las peticiones. Puede ejecutarse en nuestro ordenador o en otra máquina.

Instalar MySQL Workbench no significa necesariamente que el servidor MySQL también esté instalado y funcionando.
