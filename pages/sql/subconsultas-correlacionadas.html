Subconsultas correlacionadas y consultas avanzadas

Relacionar consultas, comprobar la existencia de filas y trabajar con tablas derivadas en MySQL.

Antes de empezar

En los apuntes anteriores ya se han utilizado subconsultas para comparar una columna con una lista mediante IN, comparar una fila con una media global y mostrar un agregado global dentro del SELECT.

Ejemplo ya conocido: 

SELECT  title,
        length
FROM film
WHERE length > (
    SELECT AVG(length)
    FROM film
);

La subconsulta anterior es independiente porque no utiliza ninguna columna de la consulta exterior.

También es escalar porque devuelve un único valor.

El contenido nuevo comienza cuando una subconsulta necesita información de la consulta exterior o cuando su resultado se utiliza como una tabla.

1. Tres formas de clasificar una subconsulta

Una subconsulta puede clasificarse según tres criterios diferentes: el resultado que devuelve, su dependencia respecto a la consulta exterior y el lugar donde aparece.

1.1. Según el resultado que devuelve

Tipo Resultado
Escalar Una columna y como máximo una fila.
De lista Una sola columna y cero, una o varias filas, utilizada como lista.
De tabla Una o varias columnas y cero, una o varias filas, utilizadas como una tabla.

1.2. Según su dependencia

Tipo Dependencia
No correlacionada Puede ejecutarse sin utilizar datos de la consulta exterior.
Correlacionada Utiliza alguna columna perteneciente a la consulta exterior.

1.3. Según su ubicación

  • Dentro de WHERE, para participar en el filtrado.
  • Dentro de SELECT, para calcular una columna del resultado.
  • Dentro de FROM, para producir una tabla derivada.

Estas clasificaciones no son excluyentes. Una misma subconsulta puede ser escalar, correlacionada y estar situada dentro de SELECT.

2. Subconsultas correlacionadas

Una subconsulta es correlacionada cuando utiliza una columna de la consulta exterior, normalmente identificada mediante un alias.

Ejemplo en world: ciudades cuya población supera la media de las ciudades de su propio país. 

SELECT  ci.Name AS `Ciudad`,
        ci.CountryCode AS `Código del país`,
        ci.Population AS `Población`
FROM city AS ci
WHERE ci.Population > (
    SELECT AVG(ci2.Population)
    FROM city AS ci2
    WHERE ci2.CountryCode = ci.CountryCode
)
ORDER BY ci.CountryCode, ci.Population DESC;

2.1. Consulta exterior

Fragmento:

SELECT  ci.Name,
        ci.CountryCode,
        ci.Population
FROM city AS ci

La consulta exterior trabaja con las ciudades y utiliza el alias ci.

2.2. Subconsulta

Fragmento:

SELECT AVG(ci2.Population)
FROM city AS ci2
WHERE ci2.CountryCode = ci.CountryCode

ci2 representa las ciudades utilizadas para calcular la media.

ci representa la ciudad que se está evaluando en la consulta exterior.

2.3. Condición de correlación

ci2.CountryCode = ci.CountryCode

Esta condición hace que la media se calcule únicamente con las ciudades pertenecientes al mismo país que la ciudad exterior.

La referencia ci.CountryCode convierte la subconsulta en correlacionada porque el alias ci se ha definido fuera de ella.

3. Cómo reconocer una referencia exterior

Para saber si una subconsulta es correlacionada, hay que comprobar dónde se ha definido cada alias. 

SELECT ci.Name
FROM city AS ci
WHERE ci.Population > (
    SELECT AVG(ci2.Population)
    FROM city AS ci2
    WHERE ci2.CountryCode = ci.CountryCode
);

El alias ci se define en la consulta exterior.

El alias ci2 se define dentro de la subconsulta.

Cuando MySQL encuentra ci.CountryCode dentro de la subconsulta, busca el alias ci fuera de ella porque no está definido en el ámbito interior.

Esta condición no crea una correlación: 

WHERE ci2.CountryCode = ci2.CountryCode

La columna se está comparando consigo misma. La condición será verdadera para cualquier valor no nulo y no conectará la subconsulta con la consulta exterior.

Condición correcta: 

WHERE ci2.CountryCode = ci.CountryCode

Una subconsulta es correlacionada por utilizar una referencia exterior, no por emplear un operador concreto.

4. Modelo mental de ejecución

Para comprender una subconsulta correlacionada, podemos imaginar el siguiente proceso lógico:

  1. La consulta exterior toma una fila.
  2. La subconsulta recibe un valor de esa fila.
  3. La subconsulta busca o calcula el resultado correspondiente.
  4. La consulta exterior utiliza ese resultado.
  5. El proceso continúa conceptualmente con las demás filas exteriores.

En el ejemplo de las ciudades, primero se toma una ciudad, después se obtiene su CountryCode, se calcula la media de las ciudades de ese país y finalmente se compara la población de la ciudad con esa media.

Este es un modelo mental para comprender la lógica, no una garantía de que MySQL ejecute físicamente la subconsulta una vez por cada fila.

El optimizador puede transformar internamente la consulta y elegir otra estrategia equivalente.

5. Subconsultas escalares correlacionadas

Una subconsulta puede ser simultáneamente escalar y correlacionada. 

SELECT  ci.Name AS `Ciudad`,
        ci.Population AS `Población`
FROM city AS ci
WHERE ci.Population > (
    SELECT AVG(ci2.Population)
    FROM city AS ci2
    WHERE ci2.CountryCode = ci.CountryCode
);

Es escalar porque AVG(ci2.Population) devuelve un único valor.

Es correlacionada porque utiliza ci.CountryCode, que procede de la consulta exterior.

5.1. Cantidad de columnas y filas

Una subconsulta escalar debe devolver una sola columna y como máximo una fila.

Resultado de la subconsulta Comportamiento
Una fila MySQL utiliza el valor obtenido.
Ninguna fila El resultado escalar es NULL.
Varias filas MySQL genera un error porque no puede utilizar varias filas como un único valor.

5.2. Matiz con las funciones agregadas

Una consulta agregada sin GROUP BY produce una fila aunque no encuentre datos que procesar, siempre que no se elimine esa fila con HAVING u otra cláusula.

Expresión Resultado cuando no hay filas que procesar
COUNT(*) Devuelve 0.
AVG(columna) Devuelve NULL.
SUM(columna) Devuelve NULL.
MIN(columna) Devuelve NULL.
MAX(columna) Devuelve NULL.

En las comparaciones con un valor individual que usamos aquí (=, >, <, >= o <=), la subconsulta debe devolver una sola columna y como máximo una fila.

Un agregado sin GROUP BY o un filtro por el valor completo de una clave primaria pueden limitar el resultado a una fila. Además, hay que seleccionar una sola columna.

6. EXISTS

EXISTS comprueba si una subconsulta devuelve al menos una fila.

Estructura:

SELECT columnas
FROM tabla_exterior AS e
WHERE EXISTS (
    SELECT 1
    FROM tabla_interior AS i
    WHERE i.columna = e.columna
);

Ejemplo en world: países que tienen al menos un idioma oficial. 

SELECT  c.Code AS `Código`,
        c.Name AS `País`
FROM country AS c
WHERE EXISTS (
    SELECT 1
    FROM countrylanguage AS cl
    WHERE cl.CountryCode = c.Code
      AND cl.IsOfficial = 'T'
)
ORDER BY c.Name;

cl.CountryCode = c.Code relaciona los idiomas interiores con el país exterior.

cl.IsOfficial = 'T' exige que el idioma sea oficial.

Si la subconsulta encuentra al menos una fila, EXISTS es verdadero y el país se conserva.

Si la subconsulta no encuentra ninguna fila, EXISTS es falso y el país se descarta.

EXISTS responde a una pregunta de existencia: no necesita recuperar los valores de las filas encontradas.

7. Qué significa SELECT 1

Dentro de EXISTS es habitual escribir SELECT 1 porque el operador no utiliza el valor seleccionado. 

SELECT 1

También podrían utilizarse SELECT * o una columna concreta sin cambiar el resultado lógico de EXISTS.

SELECT 1 comunica con claridad que solo interesa saber si existe alguna fila.

7.1. EXISTS no muestra las columnas interiores

SELECT c.Name
FROM country AS c
WHERE EXISTS (
    SELECT cl.Language
    FROM countrylanguage AS cl
    WHERE cl.CountryCode = c.Code
);

El resultado exterior solo muestra c.Name.

Aunque la subconsulta seleccione cl.Language, EXISTS no añade esa columna al resultado de la consulta exterior.

8. EXISTS y COUNT

No debe utilizarse COUNT(*) dentro de EXISTS para comprobar si existen filas.

Código problemático: 

SELECT c.Name
FROM country AS c
WHERE EXISTS (
    SELECT COUNT(*)
    FROM city AS ci
    WHERE ci.CountryCode = c.Code
);

COUNT(*) sin GROUP BY devuelve una fila incluso cuando el conteo es 0.

Como la subconsulta devuelve una fila, EXISTS resulta verdadero aunque no exista ninguna ciudad relacionada.

Código correcto:

SELECT c.Name
FROM country AS c
WHERE EXISTS (
    SELECT 1
    FROM city AS ci
    WHERE ci.CountryCode = c.Code
);

EXISTS ya realiza la comprobación de existencia y no necesita COUNT(*).

9. NOT EXISTS

NOT EXISTS conserva una fila exterior cuando la subconsulta no encuentra ninguna fila relacionada.

Estructura:

SELECT columnas
FROM tabla_exterior AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM tabla_interior AS i
    WHERE i.columna = e.columna
);

Ejemplo en world: países sin ciudades registradas. 

SELECT  c.Code AS `Código`,
        c.Name AS `País`
FROM country AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM city AS ci
    WHERE ci.CountryCode = c.Code
)
ORDER BY c.Name;

La consulta exterior toma un país y la subconsulta busca una ciudad asociada con él.

Si encuentra alguna ciudad, EXISTS sería verdadero y NOT EXISTS lo convierte en falso.

Si no encuentra ninguna ciudad, EXISTS sería falso y NOT EXISTS lo convierte en verdadero.

Operador Conserva la fila exterior cuando...
EXISTS La subconsulta encuentra al menos una fila.
NOT EXISTS La subconsulta no encuentra ninguna fila.

EXISTS busca presencia y NOT EXISTS busca ausencia.

10. EXISTS no siempre implica correlación

Es habitual utilizar EXISTS con subconsultas correlacionadas, pero el operador no crea la correlación automáticamente.

Ejemplo no correlacionado: 

SELECT Name
FROM country
WHERE EXISTS (
    SELECT 1
    FROM city
    WHERE Population > 10000000
);

La subconsulta no utiliza ninguna columna de country.

Si existe al menos una ciudad con más de diez millones de habitantes, EXISTS será verdadero para todos los países.

Si no existe ninguna, será falso para todos los países.

Una subconsulta es correlacionada porque utiliza una referencia exterior, no porque emplee EXISTS.

11. Subconsultas correlacionadas dentro de SELECT

Una subconsulta situada dentro del SELECT calcula una columna para cada fila de la consulta exterior.

Ejemplo en sakila: mostrar cada cliente y su número total de alquileres. 

SELECT  c.customer_id AS `ID`,
        c.first_name AS `Nombre`,
        c.last_name AS `Apellidos`,
        (
            SELECT COUNT(*)
            FROM rental AS r
            WHERE r.customer_id = c.customer_id
        ) AS `Total de alquileres`
FROM customer AS c
ORDER BY `Total de alquileres` DESC;

Es escalar porque COUNT(*) devuelve un solo valor.

Es correlacionada porque utiliza c.customer_id de la consulta exterior.

Está dentro del SELECT porque su resultado se muestra como la columna Total de alquileres.

11.1. Diferencia respecto a una subconsulta global

Subconsulta global e independiente: 

SELECT  rating,
        AVG(length) AS `Media del grupo`,
        (
            SELECT AVG(length)
            FROM film
        ) AS `Media global`
FROM film
GROUP BY rating;

La media global es la misma para todos los grupos porque la subconsulta no utiliza ninguna columna exterior.

Subconsulta correlacionada: 

SELECT  c.customer_id,
        (
            SELECT COUNT(*)
            FROM rental AS r
            WHERE r.customer_id = c.customer_id
        ) AS `Total de alquileres`
FROM customer AS c;

El resultado puede cambiar para cada cliente porque depende de c.customer_id.

12. Subconsultas dentro de FROM

Una subconsulta situada dentro de FROM produce un resultado que la consulta exterior puede utilizar como si fuera una tabla.

Este resultado recibe el nombre de tabla derivada.

Estructura:

SELECT columnas
FROM (
    SELECT columnas
    FROM tabla
) AS alias;

Ejemplo en sakila: crear un resumen por clasificación y filtrar después ese resultado. 

SELECT  resumen.rating AS `Clasificación`,
        resumen.Total AS `Total de películas`,
        resumen.`Duración media`
FROM (
    SELECT  rating,
            COUNT(*) AS Total,
            AVG(length) AS `Duración media`
    FROM film
    GROUP BY rating
) AS resumen
WHERE resumen.Total >= 200
ORDER BY resumen.Total DESC;

La subconsulta agrupa las películas por rating y calcula el total y la duración media de cada grupo.

El resultado interior recibe el alias resumen y la consulta exterior trabaja con él como si fuera una tabla.

Finalmente, la consulta exterior conserva los grupos que tienen al menos 200 películas.

12.1. Alias de una tabla derivada

Una tabla derivada debe tener un alias.

Código incorrecto:

SELECT *
FROM (
    SELECT  rating,
            COUNT(*) AS Total
    FROM film
    GROUP BY rating
);

Código correcto:

SELECT *
FROM (
    SELECT  rating,
            COUNT(*) AS Total
    FROM film
    GROUP BY rating
) AS resumen;

El alias se escribe después del paréntesis que cierra la subconsulta.

12.2. Columnas disponibles

La consulta exterior solo puede utilizar las columnas devueltas por la subconsulta. 

SELECT  resumen.rating,
        resumen.Total
FROM (
    SELECT  rating,
            COUNT(*) AS Total
    FROM film
    GROUP BY rating
) AS resumen;

La tabla derivada contiene rating y Total.

La consulta exterior no podría utilizar resumen.film_id porque film_id no forma parte del resultado interior.

Una tabla derivada solo expone las columnas incluidas en su propio SELECT.

13. IN, EXISTS y NOT EXISTS

13.1. IN

IN responde a la pregunta: ¿este valor aparece en la lista producida por la subconsulta?

Patrón:

WHERE Code IN (
    SELECT CountryCode
    FROM countrylanguage
);

13.2. EXISTS

EXISTS responde a la pregunta: ¿existe al menos una fila relacionada?

Patrón:

WHERE EXISTS (
    SELECT 1
    FROM countrylanguage AS cl
    WHERE cl.CountryCode = c.Code
);

13.3. NOT EXISTS

NOT EXISTS responde a la pregunta: ¿no existe ninguna fila relacionada?

Patrón:

WHERE NOT EXISTS (
    SELECT 1
    FROM countrylanguage AS cl
    WHERE cl.CountryCode = c.Code
);
Necesidad lógica Operador habitual
Comparar un valor con una lista. IN
Comprobar si existe una relación. EXISTS
Comprobar que no existe una relación. NOT EXISTS

13.4. Rendimiento

No debe memorizarse que EXISTS siempre es más eficiente que IN.

MySQL puede transformar y optimizar ambas formas mediante diferentes estrategias.

El rendimiento depende de los índices, el tamaño de las tablas, la distribución de los datos, las condiciones utilizadas y las decisiones del optimizador.

Primero debe elegirse el operador que exprese correctamente la lógica de la consulta.

14. Ámbito y ocultación de alias

Cada consulta tiene su propio ámbito.

Una subconsulta puede utilizar sus propias tablas, sus propios alias y los alias exteriores cuando es correlacionada.

Código correcto:

SELECT co.Name
FROM country AS co
WHERE EXISTS (
    SELECT 1
    FROM city AS ci
    WHERE ci.CountryCode = co.Code
);

co pertenece a la consulta exterior.

ci pertenece a la subconsulta.

14.1. Reutilizar un alias interior

Código incorrecto:

SELECT c.Name
FROM country AS c
WHERE EXISTS (
    SELECT 1
    FROM city AS c
    WHERE c.CountryCode = c.Code
);

El alias interior c de la tabla city oculta al alias exterior c de la tabla country dentro de la subconsulta.

MySQL interpreta c.Code como una columna de city. Como city no contiene una columna llamada Code, la consulta provoca un error de ejecución.

Versión correcta:

SELECT co.Name
FROM country AS co
WHERE EXISTS (
    SELECT 1
    FROM city AS ci
    WHERE ci.CountryCode = co.Code
);

Utilizar alias distintos permite reconocer inmediatamente qué tabla representa cada referencia.

15. Errores frecuentes

15.1. Confundir una subconsulta global con una correlacionada

Código problemático:

SELECT  c.Name,
        (
            SELECT COUNT(*)
            FROM city
        ) AS `Total`
FROM country AS c;

La subconsulta cuenta todas las ciudades y repite el mismo total para todos los países.

Para obtener un total diferente por país, debe relacionarse la tabla interior con la fila exterior.

Condición necesaria:

WHERE ci.CountryCode = c.Code

Para utilizar esa condición, también hay que cambiar FROM city por FROM city AS ci dentro de la subconsulta.

15.2. Comparar una columna consigo misma

Código incorrecto:

WHERE ci.CountryCode = ci.CountryCode

Para valores no nulos, la columna coincide consigo misma. La condición no conecta con la consulta exterior.

Código correcto:

WHERE ci.CountryCode = c.Code

15.3. Utilizar COUNT dentro de EXISTS

Código incorrecto:

WHERE EXISTS (
    SELECT COUNT(*)
    FROM city AS ci
    WHERE ci.CountryCode = c.Code
);

COUNT(*) devuelve una fila aunque el conteo sea 0, por lo que EXISTS resulta verdadero.

Código correcto:

WHERE EXISTS (
    SELECT 1
    FROM city AS ci
    WHERE ci.CountryCode = c.Code
);

15.4. Esperar que EXISTS muestre columnas interiores

EXISTS solo comprueba si la subconsulta devuelve alguna fila.

Las columnas seleccionadas dentro de EXISTS no se añaden al resultado exterior.

15.5. Utilizar una subconsulta escalar que devuelve varias filas

Código problemático:

WHERE Population > (
    SELECT Population
    FROM city
    WHERE CountryCode = 'ESP'
);

La subconsulta puede devolver varias poblaciones y provocar un error de ejecución.

15.6. Olvidar el alias de una tabla derivada

Código incorrecto:

FROM (
    SELECT  rating,
            COUNT(*) AS Total
    FROM film
    GROUP BY rating
)

Falta un alias después del paréntesis de cierre, como AS resumen.

15.7. Solicitar una columna que la tabla derivada no devuelve

Código incorrecto:

SELECT resumen.film_id
FROM (
    SELECT  rating,
            COUNT(*) AS Total
    FROM film
    GROUP BY rating
) AS resumen;

film_id no forma parte del resultado de la subconsulta y no está disponible para la consulta exterior.

15.8. Suponer que toda subconsulta con EXISTS es correlacionada

EXISTS no crea la correlación por sí solo.

Solo será correlacionada si utiliza alguna columna perteneciente a la consulta exterior.

16. Método para analizar una subconsulta avanzada

Antes de ejecutar una consulta, conviene responder estas preguntas en orden:

  1. ¿Cuál es la consulta exterior?
  2. ¿Cuál es la subconsulta?
  3. ¿Qué columnas y filas devuelve la subconsulta?
  4. ¿Devuelve un valor, una lista o una tabla?
  5. ¿Utiliza algún alias de la consulta exterior?
  6. ¿Qué condición conecta la consulta interior con la exterior?
  7. ¿La lógica necesita IN, EXISTS o NOT EXISTS?
  8. Si es escalar, ¿puede devolver más de una fila?
  9. Si utiliza EXISTS, ¿se están comprobando filas directamente?
  10. Si está dentro de FROM, ¿la tabla derivada tiene alias?
  11. ¿La tabla derivada devuelve todas las columnas que necesita la consulta exterior?
  12. ¿Los alias permiten distinguir claramente cada tabla?

Analizar primero la forma del resultado y después la relación entre los ámbitos evita la mayoría de errores conceptuales.

17. Resumen final

  • Una subconsulta correlacionada utiliza una columna de la consulta exterior.
  • La correlación se reconoce localizando alias exteriores dentro de la subconsulta.
  • Una subconsulta puede ser escalar y correlacionada al mismo tiempo.
  • Una subconsulta escalar devuelve una columna y como máximo una fila.
  • COUNT(*) sin GROUP BY devuelve 0 cuando no encuentra filas; otros agregados como AVG() devuelven NULL cuando no tienen valores que procesar.
  • EXISTS comprueba si la subconsulta devuelve al menos una fila.
  • SELECT 1 expresa que solo interesa comprobar la existencia de una fila.
  • EXISTS no muestra las columnas seleccionadas dentro de la subconsulta.
  • No debe utilizarse COUNT(*) dentro de EXISTS para comprobar si existen filas.
  • NOT EXISTS conserva la fila exterior cuando no encuentra ninguna correspondencia.
  • Utilizar EXISTS no convierte automáticamente una subconsulta en correlacionada.
  • Una subconsulta correlacionada dentro de SELECT calcula un valor relacionado con cada fila exterior.
  • Una subconsulta dentro de FROM crea una tabla derivada.
  • Las tablas derivadas necesitan un alias.
  • La consulta exterior solo puede utilizar las columnas devueltas por la tabla derivada.
  • Un alias interior puede ocultar un alias exterior con el mismo nombre.
  • IN, EXISTS y NOT EXISTS deben elegirse por su significado lógico.
  • No existe una regla universal que garantice que EXISTS siempre sea más rápido que IN.

La clave consiste en identificar qué devuelve la subconsulta, de qué ámbito procede cada columna y cómo utiliza el resultado la consulta exterior.
