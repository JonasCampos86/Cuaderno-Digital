Creación y manipulación inicial de tablas

Clase 2 · Crear una base de datos, definir la tabla empleados, insertar registros y consultar la información con MySQL.

1. Objetivo y recorrido de la clase

Vamos a preparar una base de datos para almacenar empleados y consultar después la información introducida.

El recorrido será:

  1. CREATE DATABASE: crear la base de datos.
  2. USE: seleccionarla para trabajar con ella.
  3. CREATE TABLE: definir una tabla.
  4. INSERT INTO: añadir registros.
  5. SELECT: consultar los datos.

Utilizaremos una base de datos llamada mi_empresa y una tabla llamada empleados.

Estructura y datos

La estructura de una tabla establece sus columnas, sus tipos de datos y sus reglas.

Los datos son los valores almacenados en las filas de esa tabla.

Por ejemplo:

Elemento Ejemplo
Nombre de la tabla empleados
Columnas id, nombre, anio_incorporacion
Tipo de una columna VARCHAR(50) para nombre
Valores de una fila 1, Ana, 2024

Crear una tabla define su estructura; insertar registros añade datos a esa estructura.

Todos los ejemplos pertenecen al mismo recorrido. Los resultados mostrados parten de una tabla nueva, con la configuración habitual de MySQL para generar identificadores.

2. Cómo leer y escribir las instrucciones

Una instrucción o sentencia SQL expresa una operación que queremos que MySQL ejecute.

Por ejemplo:

USE mi_empresa;

La instrucción indica a MySQL que seleccione mi_empresa como base de datos actual.

Elementos básicos de la sintaxis

Elemento Para qué sirve Ejemplo
Palabras clave Expresan la operación y sus componentes. CREATE TABLE, VALUES
Identificadores Nombran bases de datos, tablas o columnas. mi_empresa, empleados, nombre
Comillas simples Delimitan valores de texto. 'Ana'
Comas Separan elementos de una lista. nombre, anio_incorporacion
Paréntesis Agrupan definiciones, columnas o valores, según la instrucción. ('Ana', 2024)
Punto y coma Marca el final de cada sentencia en nuestros scripts. ;

Escribiremos las palabras clave en mayúsculas para reconocerlas fácilmente. MySQL también las reconoce en minúsculas.

Los nombres elegidos por nosotros se escribirán en minúsculas y con guiones bajos cuando tengan varias palabras.

Mantén la misma escritura en los nombres de tablas: la distinción entre mayúsculas y minúsculas puede depender del sistema y de la configuración.

Nombres y valores no son lo mismo

En una inserción:

  • nombre identifica una columna.
  • 'Ana' es un valor que queremos almacenar en ella.

El nombre de una columna indica dónde se guarda el dato; el valor indica qué dato se guarda.

Una sentencia puede ocupar varias líneas. Los saltos de línea y la sangría facilitan su lectura; no la convierten en varias sentencias.

3. Crear la base de datos: CREATE DATABASE

CREATE DATABASE crea una base de datos.

La necesitamos para agrupar las tablas de nuestra empresa. Crearla todavía no introduce empleados ni define sus columnas.

Sintaxis básica

CREATE DATABASE mi_empresa;
Fragmento Significado
CREATE DATABASE Solicita crear una base de datos.
mi_empresa Es el nombre elegido.
; Finaliza la sentencia.

Qué ocurre al ejecutarla

Antes: no existe mi_empresa.

Después: existe la base de datos mi_empresa, pero todavía no hemos creado ninguna tabla dentro de ella.

MySQL devuelve una confirmación si la operación se realiza correctamente.

Si ya existe una base de datos con ese nombre, esta instrucción produce un error.

La condición IF NOT EXISTS

Para solicitar la creación únicamente cuando la base de datos todavía no existe, utilizamos: 

CREATE DATABASE IF NOT EXISTS mi_empresa;

IF NOT EXISTS significa «si no existe».

Estado anterior Comportamiento
No existe mi_empresa. MySQL la crea.
Ya existe mi_empresa. MySQL conserva la existente y genera una advertencia por esa circunstancia, en lugar del error por nombre duplicado.

IF NOT EXISTS conserva una base de datos existente; no la vacía ni la reinicia.

En el resto de la clase utilizaremos esta segunda forma.

4. Seleccionar la base de datos: USE

La base de datos actual es la que MySQL utiliza por defecto cuando una instrucción no especifica otra.

Un servidor puede contener varias bases de datos. Antes de crear nuestra tabla, debemos indicar en cuál vamos a trabajar.

Instrucción

USE mi_empresa;
Fragmento Significado
USE Selecciona la base de datos actual.
mi_empresa Identifica la base de datos que queremos seleccionar.

Qué ocurre al ejecutarla

Antes: mi_empresa existe, pero puede haber otra base de datos seleccionada o ninguna.

Después: mi_empresa queda seleccionada para las instrucciones posteriores de esa conexión.

Por ejemplo, cuando escribamos CREATE TABLE empleados (...), MySQL creará la tabla dentro de mi_empresa.

CREATE DATABASE crea una base de datos; USE selecciona una base de datos existente.

La selección se mantiene en la conexión hasta que se cambia o esta termina. Al abrir otra conexión, no debemos dar por supuesto que conserva esa selección. Referencia: documentación de MySQL .

USE no crea una base de datos ni modifica sus tablas o registros. Si el nombre indicado no existe, la instrucción falla.

Esta es la instrucción que utilizamos en MySQL para seleccionar la base de datos; no debe suponerse que todos los motores utilizan el mismo mecanismo.

5. Tipos de datos de las columnas

El tipo de datos determina qué clase de valores puede almacenar una columna.

Para elegirlo, primero debemos pensar qué representa el dato.

En nuestra tabla:

Columna Información que representa Tipo elegido
id Un identificador numérico entero. INT
nombre El nombre del empleado. VARCHAR(50)
anio_incorporacion El año en que se incorporó. YEAR

5.1. INT: números enteros

id INT

INT permite almacenar números enteros, como 1, 25 o 300.

El tipo numérico no convierte la columna en identificador por sí solo. Tampoco lo hace el nombre id: las reglas se establecen expresamente al definirla.

5.2. VARCHAR(n): texto de longitud variable

nombre VARCHAR(50)

VARCHAR(50) permite almacenar texto de hasta 50 caracteres.

'Ana' ocupa 3 caracteres y 'Luis' ocupa 4. Ambos valores caben en esa columna.

El número de VARCHAR indica el máximo de caracteres de cada valor, no el número de filas de la tabla.

Si un texto supera ese máximo, MySQL puede rechazarlo o recortarlo con una advertencia, según su configuración. Debemos proporcionar valores que respeten el límite.

5.3. YEAR: años en MySQL

anio_incorporacion YEAR

YEAR es un tipo de MySQL para representar años. Admite los años comprendidos entre 1901 y 2155, además del valor especial 0000.

En nuestros ejemplos utilizaremos años completos, como 2024, y declararemos el tipo como YEAR, sin añadir un tamaño. Referencia: documentación de MySQL .

YEAR no admite cualquier número de cuatro cifras y tampoco representa una fecha completa: no incluye mes ni día.

6. Restricciones y generación automática

Una restricción establece una condición que deben cumplir los datos almacenados.

En esta clase utilizaremos PRIMARY KEY y NOT NULL. También emplearemos AUTO_INCREMENT, que es un atributo de generación automática.

6.1. PRIMARY KEY: identificar las filas

La clave primaria identifica de forma única cada fila de una tabla.

Los nombres no son adecuados para identificar por sí solos a nuestros empleados, porque dos personas pueden llamarse igual. Utilizaremos una columna id. 

id INT PRIMARY KEY

En esta definición, PRIMARY KEY impide que id contenga valores repetidos o NULL.

Estas filas serían válidas:

id nombre
1Ana
2Ana

Los nombres coinciden, pero los identificadores son diferentes.

Una segunda fila con id = 1 incumpliría la clave primaria.

PRIMARY KEY impide que la clave se repita o sea NULL; no genera sus valores automáticamente.

6.2. NOT NULL: impedir la ausencia de valor

NULL representa la ausencia de un valor, por ejemplo porque se desconoce. 

nombre VARCHAR(50) NOT NULL

Esta definición impide que nombre almacene NULL.

NULL y texto vacío

Valor Qué representa ¿Lo admite NOT NULL?
NULL Ausencia de valor. No.
'' Un texto de cero caracteres. Sí.
'Ana' Un texto con contenido. Sí.

NOT NULL impide NULL, pero no impide una cadena vacía ni un texto formado por espacios.

Por tanto, esta restricción no basta para garantizar que un nombre tenga contenido útil. Referencia: documentación de MySQL .

NULL se escribe sin comillas. 'NULL' sería un texto de cuatro caracteres, no la ausencia de un valor.

6.3. AUTO_INCREMENT: generar identificadores

AUTO_INCREMENT permite que MySQL genere automáticamente valores para una columna numérica.

Lo utilizaremos para no tener que calcular y escribir el identificador de cada empleado. 

id INT AUTO_INCREMENT PRIMARY KEY
Parte Función
INT Establece el tipo numérico entero.
AUTO_INCREMENT Genera el identificador cuando omitimos esa columna al insertar.
PRIMARY KEY Garantiza que el identificador almacenado no se repita ni sea NULL.

En una tabla nueva y con la configuración habitual, los primeros identificadores generados serán 1, 2, 3…

Pueden existir saltos en la numeración. Los identificadores sirven para identificar filas, no para contar cuántas hay.

AUTO_INCREMENT genera valores y PRIMARY KEY establece las reglas de identificación.

AUTO_INCREMENT es sintaxis específica de MySQL; otros motores pueden utilizar mecanismos diferentes. Referencia: documentación de MySQL .

7. Crear la tabla: CREATE TABLE

CREATE TABLE crea una tabla y define su estructura.

Antes de insertar empleados, debemos establecer qué columnas tendrá cada fila y qué reglas se aplicarán.

Diseño de nuestra tabla

Columna Tipo Restricciones o atributos Finalidad
id INT AUTO_INCREMENT PRIMARY KEY Identificar cada empleado mediante un número generado automáticamente.
nombre VARCHAR(50) NOT NULL Guardar el nombre sin admitir NULL.
anio_incorporacion YEAR Admite NULL. Guardar el año cuando lo conocemos.

Instrucción completa

Primero debe estar seleccionada la base de datos mi_empresa. 

CREATE TABLE empleados (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    anio_incorporacion YEAR
);

Cómo se interpreta

Fragmento Función
CREATE TABLE empleados Solicita crear la tabla con ese nombre.
Paréntesis exteriores Contienen las definiciones de las columnas.
Cada definición Indica el nombre, el tipo y las reglas o atributos de una columna.
Comas Separan las definiciones.
); Cierra la definición y finaliza la sentencia.

La última definición no lleva una coma antes del paréntesis de cierre.

Estado anterior y posterior

Antes: existe mi_empresa, pero todavía no existe nuestra tabla empleados.

Después: existe empleados con tres columnas y cero filas.

MySQL confirma la creación. Todavía no hay ningún empleado almacenado.

Una tabla vacía ya tiene estructura, aunque no contenga registros.

Por qué el año puede ser NULL

En anio_incorporacion no hemos establecido NOT NULL. Por eso admite la ausencia de valor.

Además, con esta definición, si omitimos esa columna al insertar, MySQL utilizará NULL. Esto nos permitirá guardar un empleado aunque todavía no conozcamos su año de incorporación.

Si ejecutas otra vez este mismo CREATE TABLE cuando empleados ya existe, MySQL devuelve un error. La sentencia no reinicia la tabla.

8. Añadir registros: INSERT INTO

INSERT INTO añade filas a una tabla existente.

La estructura ya está preparada. Ahora introduciremos los datos de los empleados.

8.1. Insertar el primer empleado

Estado inicial: empleados está vacía. 

INSERT INTO empleados (nombre, anio_incorporacion)
VALUES ('Ana', 2024);

Qué hace cada parte

Fragmento Función
INSERT INTO empleados Indica la tabla que recibirá la fila.
(nombre, anio_incorporacion) Enumera las columnas a las que proporcionaremos valores.
VALUES Introduce los valores de la nueva fila.
('Ana', 2024) Proporciona un valor para cada columna enumerada.

Correspondencia entre columnas y valores

Posición Columna Valor
Primera nombre 'Ana'
Segunda anio_incorporacion 2024

Cada valor corresponde a la columna situada en la misma posición de la lista.

El texto 'Ana' lleva comillas simples. El año 2024 se proporciona como número, sin comillas.

Omitimos id porque MySQL generará su valor mediante AUTO_INCREMENT.

Resultado esperado

id nombre anio_incorporacion
1Ana2024

La estructura sigue siendo la misma. Lo que ha cambiado es el contenido: ahora hay una fila.

8.2. Insertar otro empleado

Estado inicial: la tabla contiene a Ana. 

INSERT INTO empleados (nombre, anio_incorporacion)
VALUES ('Luis', 2025);

Resultado esperado:

id nombre anio_incorporacion
1Ana2024
2Luis2025

La nueva fila se añade a las existentes. La información de Ana permanece almacenada.

8.3. Insertar sin conocer el año

Queremos guardar a Marta, pero todavía no conocemos su año de incorporación.

Como esa columna permite NULL, podemos omitirla: 

INSERT INTO empleados (nombre)
VALUES ('Marta');

Resultado esperado:

id nombre anio_incorporacion
1Ana2024
2Luis2025
3MartaNULL

En esta inserción:

  • id recibe un valor generado automáticamente.
  • nombre recibe el valor proporcionado.
  • anio_incorporacion recibe NULL, según la definición de nuestra tabla.

Omitir una columna no elimina esa columna: su valor se determina según su definición.

Precauciones al insertar

  • El número de valores debe coincidir con el número de columnas enumeradas.
  • El orden de los valores debe coincidir con el de esas columnas.
  • Los datos deben respetar los tipos y las restricciones.
  • Repetir una inserción puede añadir otra fila con los mismos datos y un identificador diferente.

Por ejemplo, nuestra tabla permite guardar otra persona llamada Ana. La clave primaria es id; no hemos establecido que nombre sea único.

Indicaremos expresamente las columnas para que la correspondencia sea visible y no dependa del orden completo de la tabla.

9. Consultar la información: SELECT

SELECT permite obtener información mediante una consulta.

Una inserción comunica que se han añadido datos. Para pedir que MySQL nos devuelva esos datos, utilizamos una consulta.

9.1. Consultar todas las columnas

SELECT *
FROM empleados;
Fragmento Función
SELECT Indica qué información queremos obtener.
* Selecciona todas las columnas de la tabla en esta consulta.
FROM empleados Indica de qué tabla se obtienen los datos.

Como no hemos añadido ninguna condición para filtrar filas, la consulta solicita todas las filas de empleados.

Resultado esperado

id nombre anio_incorporacion
1Ana2024
2Luis2025
3MartaNULL

El resultado tiene tres columnas y tres filas. En MySQL Workbench se muestra como un resultado de consulta.

NULL indica que no tenemos un año almacenado para Marta. No significa que su año sea cero ni que se haya guardado el texto 'NULL'.

Esta consulta devuelve información sin modificar la tabla ni sus registros.

El asterisco selecciona columnas. La ausencia de un filtro es lo que hace que aquí se soliciten todas las filas.

Esta consulta no garantiza el orden de las filas. Las mostramos ordenadas por identificador para facilitar la lectura.

9.2. Consultar columnas concretas

Si solo necesitamos los nombres y los años, los indicamos expresamente: 

SELECT nombre, anio_incorporacion
FROM empleados;

Resultado esperado:

nombre anio_incorporacion
Ana2024
Luis2025
MartaNULL

La columna id continúa existiendo y conservando sus valores. Simplemente no forma parte del resultado solicitado.

Las columnas seleccionadas determinan qué devuelve la consulta, no qué columnas conserva la tabla. Referencia: documentación de MySQL .

10. Recorrido completo para practicar y repasar

Condición inicial

El siguiente bloque parte de que todavía no existe la tabla empleados dentro de mi_empresa.

Ejecutaremos las instrucciones en el orden en que aparecen. 

CREATE DATABASE IF NOT EXISTS mi_empresa;

USE mi_empresa;

CREATE TABLE empleados (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    anio_incorporacion YEAR
);

INSERT INTO empleados (nombre, anio_incorporacion)
VALUES ('Ana', 2024);

INSERT INTO empleados (nombre, anio_incorporacion)
VALUES ('Luis', 2025);

INSERT INTO empleados (nombre)
VALUES ('Marta');

SELECT *
FROM empleados;

Qué produce cada paso

Paso Instrucción Efecto
1 CREATE DATABASE IF NOT EXISTS Crea la base de datos si no existe.
2 USE Selecciona la base de datos para trabajar en esa conexión.
3 CREATE TABLE Crea la estructura de la tabla, inicialmente vacía.
4 Primer INSERT INTO Añade la fila de Ana.
5 Segundo INSERT INTO Añade la fila de Luis.
6 Tercer INSERT INTO Añade la fila de Marta con el año en NULL.
7 SELECT Devuelve los datos solicitados sin modificar los registros.

Qué sucede al trabajar desde MySQL Workbench

MySQL Workbench envía las instrucciones al servidor MySQL. MySQL las procesa sobre la base de datos y devuelve:

  • Una confirmación cuando realiza correctamente una operación.
  • Una advertencia cuando hay una circunstancia que debe comunicarse.
  • Un error cuando no puede realizar la operación.
  • Un conjunto de resultados cuando ejecutamos una consulta como la anterior.

El bloque no está preparado para ejecutarse repetidamente sin revisar el estado previo. Una tabla ya existente provoca un error en ese CREATE TABLE, y repetir los INSERT INTO puede añadir más filas.

IF NOT EXISTS solo afecta aquí a la creación de la base de datos. No protege las demás instrucciones frente a repeticiones.

Antes de ejecutar SQL, identifica sobre qué base de datos y tabla actúa, qué estado espera encontrar y qué cambiará al ejecutarse.
