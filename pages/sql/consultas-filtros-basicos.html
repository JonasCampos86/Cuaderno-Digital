Consultas y filtros básicos en SQL

Clase 3 · Consultar, filtrar, ordenar y calcular resultados con MySQL y la base de datos de ejemplo world.

1. Objetivos del tema

Este tema explica cómo:

  • Recuperar datos mediante SELECT.
  • Elegir la tabla mediante FROM.
  • Filtrar filas mediante WHERE.
  • Comparar valores mediante operadores.
  • Combinar condiciones con AND, OR y NOT.
  • Buscar patrones de texto mediante LIKE y %.
  • Comprobar varios valores mediante IN.
  • Seleccionar valores incluidos en un intervalo mediante BETWEEN.
  • Comprobar valores nulos mediante IS NULL.
  • Ordenar resultados mediante ORDER BY.
  • Limitar la cantidad de filas mediante LIMIT.
  • Crear alias mediante AS.
  • Realizar cálculos sencillos con columnas.
  • Utilizar una subconsulta básica dentro de IN.

2. Base de datos de ejemplo: world

La base de datos de ejemplo world contiene información sobre países, ciudades e idiomas.

Antes de empezar, world debe estar importada en tu servidor MySQL. USE selecciona una base existente; no la descarga ni la crea. Puedes consultar la guía oficial de instalación de world.

Para seleccionarla: 

USE world;

Las tablas utilizadas como referencia son:

Tabla Contenido Columnas utilizadas
country Información sobre países Code, Name, Continent, IndepYear, Population, GNP
city Información sobre ciudades ID, Name, CountryCode, District, Population
countrylanguage Idiomas hablados en cada país CountryCode, Language, IsOfficial, Percentage

Los resultados de esta lección son muestras del conjunto de ejemplo: no representan necesariamente todas las filas ni su orden. Las cifras corresponden a los datos de world, no a estadísticas actuales.

En los ejemplos posteriores también aparecerá esta correspondencia: 

city.CountryCode → country.Code

El valor almacenado en city.CountryCode permite identificar el país correspondiente dentro de country.Code.

3. Qué hace una consulta

Una consulta SELECT lee datos y produce una tabla de resultados, pero no modifica los datos almacenados.

Podemos entender las consultas de esta clase con este recorrido lógico:

  1. MySQL localiza la tabla indicada.
  2. Examina sus filas.
  3. Aplica los filtros solicitados.
  4. Selecciona las columnas correspondientes.
  5. Ordena o limita el resultado si se lo pedimos.
  6. Devuelve una tabla de resultados.

Este recorrido explica el resultado; el optimizador puede elegir otra estrategia interna de ejecución. La estructura y los datos originales permanecen intactos.

4. Estructura general de una consulta

SELECT columnas
FROM tabla
WHERE condicion
ORDER BY columna ASC
LIMIT cantidad;

No todas las cláusulas son obligatorias. Esta es una plantilla: sustituye columnas, tabla, condicion y cantidad por valores concretos. Los fragmentos que empiezan por WHERE, ORDER BY o IN ilustran partes de una consulta; no se ejecutan solos.

Elemento Función
SELECT Indica qué columnas o expresiones queremos mostrar.
FROM Indica de qué tabla proceden los datos.
WHERE Decide qué filas cumplen la condición.
ORDER BY Ordena las filas del resultado.
LIMIT Limita cuántas filas se devuelven.

Los corchetes que aparecen en algunas explicaciones, como [columna] o [ASC|DESC], representan opciones o elementos que deben sustituirse. No se escriben literalmente en SQL.

Orden de escritura

SELECT → FROM → WHERE → ORDER BY → LIMIT

Las cláusulas deben escribirse en este orden, aunque alguna de ellas no se utilice.

5. SELECT y FROM

5.1 Seleccionar columnas concretas

SELECT Name, Continent
FROM country;

SELECT Name, Continent indica qué columnas queremos ver. FROM country indica de qué tabla deben obtenerse.

Resultado representativo

El resultado contiene las columnas solicitadas. Estas son algunas de sus filas:

Name Continent
ArubaNorth America
AfghanistanAsia
AngolaAfrica

Las demás columnas de country continúan existiendo, pero no aparecen en este resultado.

5.2 Seleccionar todas las columnas

SELECT *
FROM country;

El asterisco * significa «todas las columnas».

Es útil para explorar una tabla, pero cuando conocemos las columnas necesarias suele ser mejor escribirlas expresamente. 

SELECT Name, Population
FROM country;

Esto hace que la consulta sea más clara y evita recuperar información innecesaria.

6. Filtrar filas con WHERE

La cláusula WHERE establece una condición.

Solamente se incluyen en el resultado las filas para las que la condición es verdadera. 

SELECT columnas
FROM tabla
WHERE condicion;

Ejemplo

SELECT Name, Population
FROM country
WHERE Continent = 'Europe';

Comportamiento

MySQL examina cada país:

  • Si su Continent es igual a 'Europe', incluye la fila.
  • Si pertenece a otro continente, descarta la fila del resultado.

Resultado representativo

Name Population
Spain39441700
France59225700
Germany82164700

La consulta no elimina los países de otros continentes. Únicamente evita mostrarlos.

7. Operadores de comparación

Los operadores permiten construir condiciones dentro de WHERE.

Operador Significado Ejemplo
= Igual que Continent = 'Europe'
> Mayor que Population > 10000000
< Menor que Population < 1000000
>= Mayor o igual que Population >= 10000000
<= Menor o igual que Population <= 1000000
<> Diferente de Continent <> 'Europe'
!= Diferente de en MySQL Continent != 'Europe'

En MySQL funcionan tanto <> como !=.

Los textos se escriben entre comillas simples: 

WHERE Continent = 'Asia'

No debemos confundir: 

WHERE Population = 10000000

con:

WHERE Population > 10000000

La primera exige una coincidencia exacta; la segunda acepta cualquier población superior.

8. Combinar condiciones

8.1 Operador AND

AND exige que todas las condiciones sean verdaderas. 

SELECT Name, Population
FROM country
WHERE Continent = 'Asia'
  AND Population > 10000000;

Cada país debe cumplir simultáneamente:

  1. Pertenecer a Asia.
  2. Tener más de diez millones de habitantes.

Un país que solamente cumpla una condición no aparecerá.

Resultado representativo

Name Population
China1277558000
India1013662000
Japan126714000

8.2 Operador OR

OR exige que se cumpla al menos una de las condiciones. 

SELECT Name, Continent
FROM country
WHERE Continent = 'Asia'
   OR Continent = 'Europe';

El resultado puede contener países asiáticos y países europeos. No contiene países de otros continentes.

8.3 Operador NOT

NOT niega una condición. 

SELECT Name, Continent
FROM country
WHERE NOT (Continent = 'Europe');

Se mostrarán los países para los que la condición Continent = 'Europe' sea falsa.

Si una comparación produce NULL, negarla también produce NULL y WHERE no incluye esa fila.

En este caso también podría utilizarse: 

WHERE Continent <> 'Europe'

8.4 Combinar AND y OR

SELECT Name, Continent, Population
FROM country
WHERE (Continent = 'Asia' OR Continent = 'Europe')
  AND Population > 100000000;

Los paréntesis agrupan la condición de pertenecer a Asia o Europa. Además, se exige que la población supere los cien millones.

Sin paréntesis, MySQL evalúa AND antes que OR. Cuando combinamos ambos operadores, los paréntesis evitan interpretaciones equivocadas.

9. Buscar patrones con LIKE

LIKE compara un texto con un patrón. 

SELECT columnas
FROM tabla
WHERE columna LIKE 'patron';

9.1 El comodín %

El comodín % representa cero, uno o varios caracteres.

Su posición determina qué buscamos:

Patrón Coincidencia
'New%' Textos que empiezan por New
'%New' Textos que terminan en New
'%New%' Textos que contienen New
'New' Coincidencia con el texto completo New

9.2 Buscar textos que empiezan por una palabra

SELECT Name
FROM city
WHERE Name LIKE 'New%';
  • New debe aparecer al principio.
  • % permite que después aparezcan cero o más caracteres.

Posibles resultados

Name
New York
Newcastle
New Orleans

9.3 Buscar textos que terminan por una palabra

SELECT Name
FROM city
WHERE Name LIKE '%City';

El texto puede comenzar de cualquier manera, pero debe terminar en City.

9.4 Buscar un texto en cualquier posición

SELECT Name
FROM city
WHERE Name LIKE '%York%';

Puede haber caracteres antes y después de York.

Sin comodines, como en LIKE 'New', se compara el texto completo según las reglas de la intercalación. Además de %, existe _, que representa exactamente un carácter. En esta clase practicamos con %.

En MySQL, que LIKE distinga entre mayúsculas y minúsculas depende de la intercalación o collation de la columna. Habitualmente las configuraciones utilizadas al empezar no hacen esa distinción, pero no es una regla universal.

10. Comprobar varios valores con IN

IN comprueba si un valor coincide con alguno de los valores incluidos en una lista. 

SELECT columnas
FROM tabla
WHERE columna IN (valor1, valor2, valor3);

Ejemplo

SELECT Name, Continent
FROM country
WHERE Continent IN ('Asia', 'Europe');

Es una forma más clara de escribir: 

SELECT Name, Continent
FROM country
WHERE Continent = 'Asia'
   OR Continent = 'Europe';

IN representa varias posibilidades para una misma columna.

Cada elemento de texto debe llevar sus propias comillas: 

IN ('Asia', 'Europe')

Para buscar esos dos valores no sería correcto escribir: 

IN ('Asia, Europe')

En el segundo caso, MySQL buscaría un único texto completo: Asia, Europe.

11. Seleccionar un intervalo con BETWEEN

BETWEEN comprueba si un valor se encuentra dentro de un intervalo. 

WHERE columna BETWEEN limite_inferior AND limite_superior

Ejemplo

SELECT Name, IndepYear
FROM country
WHERE IndepYear BETWEEN 1900 AND 2000;

Se seleccionan países cuyo año de independencia sea mayor o igual a 1900 y menor o igual a 2000.

BETWEEN incluye tanto el límite inferior como el límite superior.

La condición anterior equivale a: 

WHERE IndepYear >= 1900
  AND IndepYear <= 2000

Ejemplos de coincidencias

Name IndepYear
Australia1901
Finland1917
India1947

12. Comprobar valores nulos con IS NULL

NULL representa la ausencia de un valor conocido.

Para buscar filas que contienen NULL utilizamos: 

SELECT Name
FROM country
WHERE IndepYear IS NULL;

MySQL devuelve los países que no tienen un año de independencia almacenado.

No debemos utilizar: 

WHERE IndepYear = NULL

La comparación con = NULL produce NULL, no verdadero. Por eso WHERE no selecciona esas filas: para comprobar la ausencia de un valor utilizamos IS NULL.

La comprobación correcta es: 

WHERE IndepYear IS NULL

13. Ordenar resultados con ORDER BY

ORDER BY organiza las filas del resultado según una o varias columnas.

ORDER BY ordena las filas del resultado, pero no cambia el orden en el que los datos están almacenados en la tabla.

13.1 Orden ascendente

SELECT Name
FROM city
ORDER BY Name ASC;

En los textos, el orden ascendente suele ser alfabético de la A a la Z. En los números, va del menor al mayor.

ASC es el orden predeterminado. Por eso estas dos cláusulas piden el mismo orden: 

ORDER BY Name ASC;
ORDER BY Name;

13.2 Orden descendente

SELECT Name, Population
FROM city
ORDER BY Population DESC;

En este caso, las ciudades aparecen desde la población más alta hasta la más baja.

13.3 Ordenar mediante varias columnas

SELECT Name, Population
FROM city
ORDER BY CountryCode ASC, Population DESC;
  1. Primero se ordenan las filas por CountryCode de forma ascendente.
  2. Cuando varias ciudades tienen el mismo código de país, se ordenan entre ellas por Population de forma descendente.

La segunda columna de ordenación se utiliza cuando varias filas coinciden en la primera.

En estas consultas simples, podemos ordenar por una columna aunque esa columna no se muestre en el SELECT.

En este ejemplo, CountryCode participa en la ordenación, pero el resultado solamente muestra Name y Population.

14. Limitar resultados con LIMIT

En MySQL utilizamos LIMIT para indicar el número máximo de filas que queremos recibir. 

SELECT Name
FROM country
LIMIT 5;

MySQL devuelve como máximo cinco filas.

Sin ORDER BY, no debemos interpretar esas filas como «las primeras» según un criterio determinado. La base de datos no garantiza un orden significativo si no se lo pedimos.

Obtener los cinco países más poblados

SELECT Name, Population
FROM country
ORDER BY Population DESC
LIMIT 5;
  1. FROM localiza la tabla.
  2. ORDER BY Population DESC ordena desde la población mayor.
  3. LIMIT 5 conserva solamente las cinco primeras filas del resultado ordenado.

Para obtener los primeros o últimos elementos según un criterio, debemos combinar ORDER BY y LIMIT. Si hay empates y necesitamos un resultado reproducible, añadimos una columna única como criterio de desempate.

15. Crear alias con AS

Un alias es un nombre temporal utilizado en el resultado de una consulta. 

SELECT Name AS nombre_pais
FROM country;

La columna original continúa llamándose Name dentro de la tabla. El alias solo cambia el encabezado mostrado en el resultado.

AS no renombra ni modifica la columna almacenada.

15.1 Alias con espacios

En MySQL podemos delimitar un alias con espacios mediante acentos graves: 

SELECT Name AS `Nombre del país`
FROM country;

Los caracteres utilizados son acentos graves: 

`

Para evitar ambigüedades, reservaremos las comillas simples para los valores de texto: 

WHERE Continent = 'Europe'

En los alias que contengan espacios utilizaremos acentos graves.

16. Realizar cálculos con columnas

Podemos utilizar los valores de una columna para calcular una columna nueva en el resultado. 

SELECT
    Name AS `Nombre del país`,
    Population / 1000000 AS `Población (millones)`
FROM country;

Para cada país:

  1. MySQL toma el valor de Population.
  2. Lo divide entre 1000000.
  3. Muestra el resultado bajo el alias Población (millones).

Resultado representativo

Nombre del país Población (millones)
Spain39.4417
France59.2257
Germany82.1647

La población almacenada no cambia.

16.1 Evitar divisiones entre cero

SELECT
    Name,
    GNP / Population AS relacion_gnp_poblacion
FROM country
WHERE Population > 0;

La condición Population > 0 hace que este cálculo se aplique a las filas con poblaciones superiores a cero.

Antes de dividir entre una columna, debemos considerar si puede contener el valor cero.

Este ejemplo enseña una operación matemática entre columnas. Para interpretar económicamente el resultado habría que conocer y ajustar correctamente las unidades de GNP.

17. Subconsulta básica dentro de IN

Una subconsulta es una consulta situada dentro de otra consulta.

El siguiente ejemplo busca ciudades pertenecientes a países europeos: 

SELECT Name
FROM city
WHERE CountryCode IN (
    SELECT Code
    FROM country
    WHERE Continent = 'Europe'
);

Consulta interior

SELECT Code
FROM country
WHERE Continent = 'Europe';

Obtiene los códigos de los países europeos.

Resultado conceptual

ESP
FRA
DEU
ITA
...

Consulta exterior

SELECT Name
FROM city
WHERE CountryCode IN (...);

Los puntos suspensivos representan el lugar de la subconsulta: no se escriben literalmente. La consulta exterior comprueba si el CountryCode de cada ciudad aparece entre los códigos obtenidos por la consulta interior.

Interpretación lógica

  1. La subconsulta obtiene los códigos de los países europeos.
  2. IN utiliza esos códigos como posibilidades.
  3. La consulta exterior compara cada city.CountryCode con esos valores.
  4. El resultado contiene nombres de ciudades pertenecientes a países europeos.

La subconsulta interior debe devolver la columna cuyos valores necesita comprobar la consulta exterior.

En este caso: 

city.CountryCode → country.Code

En este tema solo se utiliza este patrón básico. Los demás tipos de subconsultas quedan fuera de su alcance.

18. Combinar varias cláusulas

SELECT
    Name AS ciudad,
    Population AS poblacion
FROM city
WHERE Name LIKE 'New%'
  AND Population > 100000
ORDER BY Population DESC
LIMIT 5;

Interpretación paso a paso

  1. FROM city: utiliza la tabla de ciudades.
  2. WHERE Name LIKE 'New%': conserva las ciudades cuyo nombre comienza por New.
  3. AND Population > 100000: exige además una población superior a cien mil habitantes.
  4. SELECT Name AS ciudad, Population AS poblacion: selecciona las columnas y asigna alias a sus encabezados.
  5. ORDER BY Population DESC: ordena desde la ciudad más poblada hasta la menos poblada.
  6. LIMIT 5: devuelve como máximo cinco filas.

19. Errores frecuentes

Error Problema Forma correcta
WHERE Continent = Europe El texto no está entre comillas. WHERE Continent = 'Europe'
WHERE IndepYear = NULL La comparación no devuelve verdadero. WHERE IndepYear IS NULL
LIKE 'New' esperando más texto El patrón 'New' no contiene comodines. LIKE 'New%'
IN ('Asia, Europe') Es un único texto. IN ('Asia', 'Europe')
LIMIT 5 para obtener los cinco mayores No existe un criterio de ordenación. ORDER BY columna DESC LIMIT 5
LIMIT antes de ORDER BY Las cláusulas están desordenadas. ORDER BY ... LIMIT ...
Usar comillas simples para nombres técnicos Pueden confundirse con valores de texto. Acentos graves para alias con espacios
Dividir sin comprobar el divisor El divisor podría valer cero. WHERE Population > 0
